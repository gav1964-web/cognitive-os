# Условные модели возвращаемых флагов — 2026-09-17

Пакет добавил проверяемый анализ узкого фрагмента Python, но не исправил
главную смысловую ошибку Replay. Четыре простых контрольных случая дали
ожидаемый ответ. В реальном описании COS всё ещё превращает диагностические
флаги в гарантию. Баллы ролей не повышены; независимой сертификации нет.

## Пять работ

1. `project_description` 0.11.0 извлекает из полной функции терминальный
   фрагмент: присваивания Boolean-выражений полям словаря и условный `raise`
   перед возвратом этого словаря. Источники привязаны к SHA256; чужой код не
   исполняется. Неподдерживаемые конструкции получают явный отказ от анализа.
2. Конечная модель перебирает до 64 сочетаний шести предикатов, сохраняет
   условный пример возврата с ложным флагом и различает его с исключением
   перед возвратом. Для простого сравнения с целым литералом вычисляет
   значения на границе и по обе стороны от неё.
3. Опциональный анализ связан с v4 claim job, исходниками и обязательством
   `return_flag_scope`. Повторная проверка заново выводит анализ из источников;
   подмена результата даже с пересчитанным digest не проходит. Старые задания
   и обычные запросы сохраняют прежний формат.
4. CLI `prepare --return-flags selectors.json` и отчёт показывают ограничения
   анализа. Полный review автоматически получает дополнительные данные после
   запроса Python-функций. Дополнительного обращения к LLM для этого нет.
5. Выполнены контролируемая проверка настоящего Replay API, четыре общих
   LLM-контроля, review спорного final-утверждения и полный маршрут описания.
   Ответы модели сохранены отдельно от решения ассистента по исходникам.

## Ограничения механизма

Модель предполагает достижение анализируемого фрагмента, обычные операции
словаря и независимые Boolean-значения. Она не доказывает достижимость всей
функции, совместимость предикатов, свойства вызывающих сторон или программы.
Даже постоянное истинное сравнение в этой абстракции может получить ложное
значение. Поэтому `false_return_witness` — условная трасса модели, а не
исполненный контрпример проекта. `semantic_verified` остаётся `false`.

Лимиты: до трёх функций, шести предикатов на функцию, 4000 символов цитаты
фрагмента, 12000 символов списка аналитических записей. Передача дополнительной
структуры ограничена отдельно от существующего бюджета исходных выдержек.
Автоматическая ветка работает после lookup функции; без lookup анализ не
добавляется. Поддержка других языков и произвольного потока управления не заявлена.

Знание и правила принадлежат плагину; runtime связывает источники, вызывает
компетенцию и организует review. Названий проектов и ожидаемых ответов в
производственных правилах нет.

## Измерение

Receipt: `artifacts/return_flags_20260917/summary.json`.
Разбор: `semantic_review.json`; исходные ответы: `*_report.json`.

| Случай | Ответ COS | Оценка по источникам |
| --- | --- | --- |
| Флаг сообщает сравнение, но не прерывает возврат | refuted | Верно |
| Ложный флаг вызывает исключение перед возвратом | supported | Верно в заявленной области обычных Boolean/dict операций |
| Для целого нуля `amount >= 0` якобы ложно | refuted | Верно |
| Флаг возвращает неизвестная внешняя функция | uncertain | Обоснованная неопределённость |
| Гарантия неизменности Replay | В целом uncertain, сама гарантия supported | Целевая ошибка осталась |

В последнем случае неопределённость вызвана связью с Cognitive OS. Модель
прямо признала, что флаги могут быть ложными и не предотвращают изменение,
но переинтерпретировала гарантию как цель. Предложение отклонено ассистентом:
`replay_claim_decision.json`. Общий `uncertain` не засчитан как исправление.

Отдельный `replay_probe.json` исполняет настоящую
`qualify_candidate_in_sandbox` с четырьмя подменёнными зависимостями в тестовом
каталоге. Два повтора с неизменным состоянием возвращают истинные флаги;
два с внедрённым изменением — `qualified` и три ложных флага. Git и тесты
кандидата не запускались. Это проверка реакции API на сообщённое изменение,
не наблюдение естественного сбоя полного Replay. Источники не изменились.

Полное описание сохранило функции freeze/validate, которые прежний review
удалял. Однако сохранились ложная гарантия неизменности, два запуска pytest
вместо двух baseline и одного fixed, неверное описание содержимого oracle,
неоговорённая необходимость валидного профиля и смешение digest с подписью.
Аналитический пакет был в финальном запросе. Улучшение сохранности публичного
API не доказывает причинный эффект нового анализа: одновременно используется
дедупликация контекста из предыдущего этапа. Черновик получен из кэша шлюза.
Полное описание не принято в product_context.

Всего 8 обращений, включая 1 cache hit по данным шлюза; **47 827 reported
tokens**: 40 881 входных и 6946 выходных. Время запросов — 199,649 секунды.
Заранее зарезервировано 727 572 токена, повторов и fallback нет, неизвестного
usage нет. Это телеметрия COS, не счёт провайдера и не расход сессии разработки.
Серия закрыта. Малые примеры авторские, независимого holdout и исходного
замера без механизма на них нет; причинный прирост качества не установлен.

## Проверки и продолжение

Итоговый `verification.json` связывает canonical, проверку двух подпроектов,
обязательную финализацию и регрессии на зафиксированном снимке. Проверки
охватывают hash binding, подмену доказательств, границы, неподдерживаемый код,
отсутствие исполнения исходников и доставку анализа после lookup. Полная
тестовая батарея всего репозитория не запускалась; используется профильная.

Следующий пакет: (1) явная связь утверждения с субъектом, областью и
предикатом; (2) структурное различение сообщения о результате и обеспечения
условия; (3) отклонение внутренне противоречивого заключения с сохранением
неопределённости, без автоматического объявления условной трассы фактом;
(4) контроли на вариантах формулировок, неполных функциях и вызывающих сторонах;
(5) ограниченное сравнительное измерение после фиксации реализации.
Очередной одинаковый self-review не заменяет эти работы.
