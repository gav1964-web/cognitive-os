## Ограничения оценивания

После первого автоматического черновика исправлены ошибки оценщика:
неоднозначность list/tuple в JSON-примере, формат status-ответов и отсутствующий
тест дубликатов без updates. Семантическая оценка принимает эквивалентные пары
и безопасные set/reversed; их нарушение исходного builtin-контракта отмечено
отдельно. Исправления одинаковы для всех, модельные ответы не редактировались.
Этот пересмотр делает рейтинг exploratory, а не независимой сертификацией.
Подробности: [поправка оценщика](../../artifacts/model_comparison_20260918/grading_amendment.md).

## Пять согласованных работ

1. Модельное сравнение ремонта: общий малый ремонт проверен у всех доступных
   ответов; native baseline Toml-sort актуален33passed/1failed/2xfail.
   Новые native model repairs пока не запущены, Reviewer не достигнут.
2. Локализация потери решения: в двух ответах правильный инвариант расходится
   с кодом для base-only duplicates. Это свидетельство конкретного перехода,
   но не доказательство причины прежних неудач Toml-sort.
3. Проверки описаний: plugin0.16.0 расширяет существующий анализ свойств
   ограниченными try/except/else/finally. Обработанная ошибка не равна успеху;
   неперехваченное исключение сохраняется, finally учитывает возврат/мутацию.
   Неизвестные операции и типы исключений не становятся доказанными.
4. Переносимость: новые авторские контрасты сопоставлены с CPython; показаны
   как отсутствующий обязательный профиль, так и действительно рабочий default.
   Это calibration, не независимый holdout. Полные тексты ещё не сравнены.
5. Закрепление: defaults не изменены; текущие status/plan/task index отделены
   от сохранённой истории. Новые роли9.7+ не заявлены.

## Расход и причина паузы

13 реальных запросов. Известный расход25069 токенов; четыре ответа GigaChat
имеют неизвестный расход. Gateway normalize_usage_for_response подставляет
нули при отсутствующем usage. Ошибка COS: прежний settle_call принимал ноль
за известный расход, поэтому последовательность продолжилась. Аудит после
пакета обнаружил это; исходные receipts сохранены, ledger исправлен на unknown.
Теперь нулевые заглушки не закрывают учёт. Новые вызовы остановлены.
Из оставшихся слотов не использован ни один; подготовка native baseline — offline.

Предварительный резерв всех21 запросов966292 токена, строго меньше1млн.
За четырьмя unknown сохранён резерв137920. Это консервативная оценка, не счёт
провайдера. Отправлен вопрос о продолжении с полным резервом неизвестных вызовов.
Пока разрешение не получено, действует остановка из DEVELOPMENT_TASKS.md.
Новый allow_unknown_reservations оставляет unknown и полный резерв, сохраняет
лимит пакета и запрет одновременных/повторных вызовов; по умолчаниюFalse.
