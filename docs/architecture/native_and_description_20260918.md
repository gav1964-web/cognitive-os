# Native repair и расширение проверки описаний

18 сентября 2026. Пользователь уточнил план: выполнить ремонт и **не откладывать**
расширение проверок описаний. Оба направления выполнены в ограниченной серии.
Ремонт не принят; новый режим проверки реализован и остаётся opt-in.

## Toml-sort: наблюдения не привели к исправлению

Проверены исходники, nomination, native observations и десять сохранённых receipts.
Свежий baseline: **33 passed / 1 failed / 2 xfailed**. В модель отправлен ровно
тот запрос, который был подготовлен 15 сентября: исходные assertions, наблюдения
двойной записи комментария и предыдущий неудачный кандидат. Ручной reference
в запрос не добавлялся; ассистент с ним знаком, поэтому опыт не независимый.

Один запрос DeepSeek через текущий L4.5-профиль: **5 991 reported tokens**.
Ответ содержал лишнее верхнеуровневое `candidate_id`; производственный контракт
его отклонил (`candidate_response_schema`). Повторов не было; Developer delivery
и final Reviewer не достигнуты. Принятых ремонтов **0**.

Для отдельной диагностики ассистент удалил только лишнее поле метаданных и
проверил **неизменённый предложенный моделью код** в копии. Это ручная проекция,
не принятый COS ответ. Полная suite: **27 passed / 7 failed / 2 xfailed** — исходный
дефект остался, добавлены шесть регрессий. Четыре сочетания header/footer дают
прежние результаты, включая дублирование при двух включённых флагах. Объяснение
модели ошибочно связывает дублирование комментария с добавлением пустой строки.
Исходный проект не изменён.

В эксперименте отключены необязательные L3.5/L4 вызовы общего анализа с явным
переходом на существующий deterministic fallback. До вызова модели исправлены
локальные настройки runner: пути выделенных пакетов и передача сохранённых
повторных наблюдений в chain_case. Эти вмешательства не считаются автономностью.
После измерения direct prompt уточнён: единственный верхнеуровневый ключ —
`candidates`, `candidate_id` запрещён. Эффект уточнения новым вызовом не измерялся;
строгость допуска и код кандидата не изменены.

Следующий repair должен проверять причинную гипотезу о совместной работе
header/footer и обоснованность nomination. Не повторять тот же запрос, не
подменять диагноз числом собранных наблюдений, не засчитывать ручной reference.

## Project-description 0.13.0

Новая опция `prepare --return-property property.json` фиксирует **до** модельного
ответа путь, символ, поле, диапазон текста `[claim_start, claim_end)` и вид
свойства: `normal_return_field_true` либо `describes_diagnostic`. Индексы относятся
к символам Python-строки исходного утверждения. Source hash добавляет runtime.
Правильность смыслового соответствия поля утверждению остаётся ответственностью
рецензента; автоматический выбор свойства не заявлен.

Плагин владеет схемой, локальной инструкцией, анализом и правилом проверки.
Runtime связывает источники и повторно проверяет receipt. Новый режим отделён
от suffix/mechanism режимов и использует прежний ответ v4 `parts/coverage/proposed_text`.
Модель не может обойти выбранное свойство метками `reports` или `other_code`.

Ограниченный анализ рассматривает все комбинации `False/True/None` для параметров
малых функций: до шести параметров, не более 64 комбинаций, до семи видимых функций
и ограниченная глубина вызовов. Поддержаны присваивания, обычные словари,
ветвления, ранние возвраты, raise и локальные функции. Соблюдается короткое
замыкание Boolean-операторов и цепочек сравнений. Исходники не исполняются.

Результаты — `holds_in_model`, `counterexample_in_model`, `no_normal_returns`,
`unknown`. Это модель ограниченного домена, не доказательство для произвольных
Python-значений. Циклы, try/finally, неизвестные вызовы, неподдержанные сигнатуры,
рекурсия и превышение бюджета не дают положительного результата. Неявный возврат,
отсутствующее поле и отсутствие нормальных возвратов не считаются доказательством.

Если явное свойство гарантии не установлено, соответствующие `supported` части
понижаются до `uncertain`. Другие части и исходный ответ сохраняются. Сам guard
не создаёт `refuted` или `supported`. Диагностическое описание не обязано возвращать
только True. Повторная проверка job/proposal пересчитывает анализ и выявляет
подмену свойств, источников, инструкции и аудита даже после пересчёта внешнего digest.

## Результаты шести обращений

| Случай | Мнение модели | Итог COS |
| --- | --- | --- |
| Диагностическое поле | supported | supported |
| Локальный guard | supported | supported |
| Ранний возврат False | refuted | refuted |
| Guard в вызывающей функции | supported | supported |
| Неизвестный backend | uncertain | uncertain |
| Исходная гарантия Replay | supported, ошибка | uncertain, понижение guard |

Контракты **6/6**, пять малых контролей **5/5** по исходному смысловому ожиданию.
Это знакомые авторские примеры и по одному ответу. Одновременно изменены инструкция
и свидетельства; независимого переноса и изолированного причинного эффекта нет.

**Replay модель всё ещё понимает неправильно.** Анализ его полной функции сообщает
`unknown` (в частности, неподдержана keyword-only сигнатура и сложный поток).
Новое правило предотвращает подтверждение выбранной гарантии при таком результате;
оно не доказало реальную изменяемость репозитория и не исправило весь текст.
Полный маршрут описания в этой серии не запускался и default не менялся.

Дополнительное offline сравнение применяет guard к прежним мнениям после явного
удаления старых полей mechanisms и suffix coverage. Положительные случаи сохраняются,
ошибочные гарантии становятся uncertain. Это проекция сохранённых ответов, не новые
ответы модели. Первая неполная проекция была отклонена за несовпадение coverage;
оба результата сохранены отдельно.

## Бюджет, проверки и дальнейшая работа

Всего **7 обращений / 23 924 reported tokens**, без cache hits, повторов и fallback.
Общий резерв до запусков — 577 388 при лимите ниже миллиона. Это телеметрия COS,
не счёт провайдера и не расход сессии ассистента. Ролевые баллы не повышены.

После живой серии исправлена найденная при code review ошибка порядка вычисления
цепочек сравнений; отдельный тест с изменяющим словарь helper проверяет реальную
семантику Python. Все шесть сохранённых анализов пересчитаны и совпали с исходными;
новых модельных обращений не было. Исходный хеш серии и хеш исправления сохранены.

Проверки описаний остаются активным направлением по уточнению пользователя.
Следующий шаг — свежие контрасты и проверяемые предусловия API (в частности,
валидность environment profile), сохранение верных деталей и один полный текст.
Расширять поддержанный язык следует по конкретным измеренным пробелам. Не
выдавать отказы на сложном коде за рост смысловой точности.

Доказательства: `artifacts/native_and_description_20260918/`:

- `protocol.json`, `token_budget.json`, `summary.json`, `semantic_review.json`;
- `repair_result.json`, `repair_attempts.json`, `repair_baseline.json`,
  `repair_candidate_full.json`, `repair_preservation_controls.json`;
- `*_property_job.json`, `*_property_report.json`, `property_offline_projected.json`;
- `post_measurement_fix.json`, `verification.json`.

Профильные тесты проверяют соответствие ограниченной модели обычному Python на
авторских fixtures, положительные/отрицательные пути, CLI и подмену provenance.
Финальная запись проверки содержит точный scope, архитектурный/400-line gate,
регрессию на снимке и проверки установленных подпроектов.
