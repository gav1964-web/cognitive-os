## Что исправлено в COS

1. В development_quality разделены `baseline_expectations.classification` и
   `case_plan.kind`; совместимость с непротиворечивым старым форматом сохранена.
2. Отсутствующую категорию покрытия можно рассмотреть вместе с содержательными
   замечаниями за один аудит. Это не допуск: все ошибки должны быть устранены;
   синтаксис, baseline, native witness, frozen tests и continuity сохраняют gates.
3. Политика требует полного первого обзора существенных обязательств, сохранения
   уже проверяемых случаев и обоснования новых комбинаций условиями исходника.
4. Исчерпание бюджета/числа вызовов немедленно завершает текущий цикл. На сохранённом
   сбое повторные native-прогоны сократились с трёх до одного; resume остаётся явным.
5. Только spec_auditor получает предел8192 выходных токенов до резервирования.
   В14 прежних аудитах максимум4300. Лимит32768 для спецификаций и кода сохранён;
   недостаточный/обрезанный ответ не принимается автоматически.

## Ошибки организации и дальнейшая работа

Ответственность ассистента: общий последовательный бюджет и дорогие повторы
не оставили равного ресурса поздним задачам; повтор первой задачи с нуля оказался
дороже, чем предварительное воспроизведение сохранённого сбоя. Нельзя объяснять
весь неуспех слабостью модели или только придирками аудитора. Формулировка web-задачи
также сочетает сохранение старой валидации с требованием отвергать invalid origin;
для неhashable origin старый код выбрасывает TypeError. Эта неоднозначность ослабляет
вывод о единственной причине первого отказа Architect.

Следующий инженерный приоритет — проверяемый реестр обязательств спецификации:
источник/goal → утверждение → native-результат → статус аудита, с различением
пропущенного раньше, нового и регрессировавшего замечания. Политика уже просит такой
обзор, но сама просьба проблему не устранила. Не разрешать одобрение ради экономии.
Последние ошибки воспроизведены offline. Следует разделять в тестах проверку нового
поведения и сохраняемые утверждения, чтобы первый feature-gap не маскировал
неверное ожидание preservation; проверить компактную передачу изменений
без потери тестов/контекста. Затем один ограниченный полный цикл с заранее
зарезервированным ресурсом завершения. Новая широкая пятёрка — после этого.
