# Синтезатор шаблонов исправлений: прототип и проверка, 3 октября 2026

Вопрос: можно ли обобщать проверенные исправления в исполняемые шаблоны без LLM,
чтобы сильная модель не была нужна на шаге обобщения. Прототип по образцу
Getafix (иерархическая анти-унификация AST правок). LLM-вызовов 0.

## Устройство

| Модуль | Ответственность |
|---|---|
| `runtime/fix_template_tree.py` | Единообразное дерево AST, анти-унификация пары правок с общей таблицей подстановок, сопоставление, подстановка, печать |
| `runtime/fix_template_mining.py` | Офлайн-извлечение замен одного оператора из коммитов-исправлений (`fix/bug/error/...` в заголовке, ≤3 production .py) |
| `runtime/fix_template_learning.py` | Агломеративное слияние правок одной формы (куча кандидатов, вся иерархия сохраняется), ранжирование, фильтр по неизменённому коду |
| `tools/fix_template_study.py` | Оценка: leave-one-project-out и хронологическое разбиение |

Шаблон исполним, только если каждая дыра в «стало» связана дырой в «было».
Правильность засчитывается при AST-совпадении предложения с правкой человека.
Ложные тревоги — срабатывания на текущем коде проекта. Фильтр (как в Getafix)
отбрасывает шаблон, если его «было» на неизменённом коде обучающих проектов
срабатывает чаще, чем число поддерживающих исправлений.

Извлечение строго офлайновое (`GIT_NO_LAZY_FETCH=1`, `--no-renames`).
Важно: первый запуск без этого флага неявно докачал с GitHub часть старых
версий файлов more-itertools (частичный клон `blob:none`); процесс остановлен.
Затем по разрешению пользователя для 6 частичных клонов выполнен
`git fetch --refetch --filter=blob:limit=1m origin` (+~7 МБ).

## Данные

9 репозиториев с полной историей: more-itertools, pyTooling, tox, pipx,
add-trailing-comma, astpretty, pytest_httpx, uritemplate, сама COS. Остальные
4321 проект корпуса — неглубокие клоны без истории. **815 правок**; COS не дала
правок (её исправления затрагивают больше трёх файлов).

## Результаты

| Протокол | Предложено | Верно | Тревог на текущем коде |
|---|---:|---:|---:|
| Между проектами, все шаблоны | 151 из 815 | **3** | 3855 на 19 280 операторов |
| Между проектами, шаблоны ≥2 проектов | 5 | 1 | 103 |
| Между проектами, с фильтром | 0 | 0 | 14 |
| Во времени (70%→30%), все шаблоны | 15 из 245 | 0 | 1464 на 19 тыс. |
| Во времени, с фильтром | 0 | 0 | 1 |

Повторяемость: при обучении на всех 815 правках шаблоны покрывают 99 правок (12%),
почти все — повторы внутри одного проекта (часто одного коммита). Межпроектных
шаблонов 4, покрывают **7 правок (0,9%)**, и это не знание об исправлениях, а
формы правки: «убрать одно условие из `or` в `if`», «убрать именованный аргумент».
Цифры — после исправления ошибки анти-унификации (одноимённые дыры разных шаблонов
считались одной переменной); до исправления было 76 предложений и 1720 тревог, вывод тот же.
Верные межпроектные предложения: удалить `choices=[...]` у `add_argument` (2, tox)
и упростить условие `r < 0 or r > n` (1, more-itertools).

## Выводы

1. Механизм работает (юнит-тесты, верные предложения на чужом коде), но на
   истории обычных проектов однооператорные исправления почти не повторяются
   синтаксически между проектами. Обобщение без LLM здесь не даёт знания.
2. Без указания, *где* дефект, шаблоны либо слишком общие (тысячи тревог), либо
   после фильтра молчат. Getafix работал в паре с анализатором, который указывал
   место и класс ошибки; у pickle-компетенции COS тоже есть свой детектор.
   Значит, накапливать имеет смысл знания для классов, у которых есть детектор
   (предупреждение анализатора, тип исключения в упавшем тесте).
3. Ограничение данных: 9 проектов, 815 правок. Отрицательный результат не
   доказывает невозможность на масштабе тысяч проектов, но показывает, что без
   локализующего детектора и большой выборки ждать переноса не следует.

## Привязка к детектору (ruff)

По разрешению пользователя склонированы с GitHub полные истории 46 известных
библиотек корпуса (основная ветка, файлы ≤1 МБ, ~1 ГБ) в
`artifacts/fix_templates_20261003/repos`; ruff 0.16 установлен в dev venv.
Всего 56 репозиториев. `tools/fix_template_detector_mine.py` берёт все
коммиты с 1–3 рабочими .py, читает версии одним `git cat-file --batch`, запускает
ruff один раз на все версии (все правила, кроме стиля документации/аннотаций,
`--isolated`). Правка привязана к правилу R, если R было внутри заменённого
оператора и нет внутри замены (`runtime/fix_template_detector.py`).
Итог: **5166 привязанных правок, 313 правил**; 124 правила имеют ≥8 правок
из ≥3 проектов (4605 правок). 58% правок относятся к диагностикам, у которых
ruff уже имеет встроенный автофикс.

Оценка (`tools/fix_template_detector_study.py`), для каждого правила и каждого
проекта: шаблоны учатся на других проектах. История — предложение в привязанном
операторе, верно = AST-совпадение с правкой человека. Текущий код — шаблоны
применяются только к операторам с предупреждением R; проверка детектором:
файл разбирается, R исчезло, новых предупреждений нет. Без детектора — те же
шаблоны на всех операторах первых 60 файлов.

| Срез | Правок | Предложено | Верно | Автофикс ruff верно |
|---|---:|---:|---:|---:|
| Все 124 правила | 4605 | 1236 | **393** (32%) | 824 из 2726 применимых |
| 55 правил без автофикса ruff | 1832 | 397 | **86** (22%) | — |

Текущий код: детектор нашёл 23 188 мест; шаблоны предложили 1277 правок,
**545 подтверждены детектором**. Без детектора те же шаблоны дают
**69 975** срабатываний — детектор сокращает шум примерно в 55 раз.

Правила с ≥5 предложениями и точностью ≥50%: 14. С автофиксом ruff:
B028, F541, UP028, E713, F841, TRY201, F632, SIM118, UP008 (шаблоны лишь
повторяют существующий инструмент). Без автофикса: **G002** (8/16), **TRY004**
(8/9, на текущем коде 19/19 подтверждены), **TID252** (6/12), **A004** (3/5),
частично SIM105 (9/18).

### Вывод по привязке

1. Детектор превращает обобщение без LLM из шума в рабочий механизм: от 3 до
   393 верных воспроизведений правок людей на чужих проектах, и 545 правок
   текущего кода подтверждены автоматически. Цикл детектор → история → шаблон
   → проверка детектором идёт без LLM; сильная модель нужна, чтобы его построить.
2. Но там, где он работает лучше всего, знание уже скомпилировано людьми в
   инструмент (автофикс ruff). Новое знание — 86 верных правок по 55 правилам
   без автофикса; полезную точность дают единицы правил.
3. Статические детекторы видят в основном стиль, модернизацию и простые
   ошибки. Смысловые задачи рабочего маршрута COS (границы эллипса, цепочки
   алиасов) они не находят, поэтому этот путь их не покрывает.
4. Ограничения: точность считается по точному совпадению с человеком (занижает
   допустимые альтернативы); проверка детектором не доказывает смысловую
   корректность; один анализатор и одна версия Python для разбора.

## Подключение TRY004 и G002 к `--competency-first`

Плагин `plugins/learned_fix_templates` 0.1.0 владеет выученными шаблонами
(`tools/fix_template_export.py`: обучение на всех привязанных правках правила,
только шаблоны с поддержкой ≥2 проектов, provenance и метрики LOPO в KB).
Каталог `config/task_competencies.json` (v2) объявляет для него детектор ruff.
Маршрут `runtime/feature_competency.py` запускает детектор на копии проекта,
передаёт диагностики, а предложение без новых тестов проверяет детектором:
заявленные диагностики исчезли на заявленных местах, новых нет; исходы
ссылающихся тестов не изменились. TRY004 меняет тип исключения, поэтому требует
существующих ссылающихся тестов, проходящих хотя бы раз на исходнике. G002
защищён проверкой «число плейсхолдеров = числу позиционных аргументов».

Проверка на проектах пользователя (копии, без установки, LLM 0), 22 файла с TRY004:
