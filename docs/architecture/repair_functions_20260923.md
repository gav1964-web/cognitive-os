# Межмодульная область ремонта, 23 сентября 2026

Владелец: подсистема roles, инфраструктура source-bound development trials.
Это общий Python-механизм, без знаний о форматтерах, именах проектов или их
правильном исправлении. Доменная KB в общий runtime не добавляется.

`trace_failure_methods(..., source_files=[...])` и
`tools/nominate_repair_target.py --source-file <relative.py>` включают новый путь.
Без явного списка сохраняется прежний режим методов одного класса.
Список ограничен 64 production-файлами, 4 MB суммарно и 512 функциями.
Тестовые файлы, внешние пути, symlink и неучтённые inventory-файлы запрещены.

Каталог читает AST и компилирует код без импорта проекта. Во время двух
native-replay в копиях проверяются реальные code identities. Отбираются только
top-level функции, выполненные внутри единственного вызова наблюдаемого API
в упавшем утверждении. Обычные функции и generator callbacks допустимы;
наблюдаемый entrypoint должен быть обычной синхронной функцией.
Декоратор не является основанием доверия: должна выполниться именно проверенная
функция из исходника. Runtime-подмена её code object отклоняется.

Новые схемы: `repair_function_trace.v1` и
`repair_function_nomination_context.v1`. Поле `methods` сохранено для совместимого
handoff, но строки содержат `callable_kind` и хеш собственного файла.
`file_sha256_by_target` заменяет предположение о единственном файле.
Рёбра показывают ближайших известных предков стека; они могут проходить через
внешний или вложенный helper. Регистрация отложенного callback и общий data flow
не доказаны. Значения аргументов не собираются.

Nomination остаётся advisory: исполнение функции не доказывает корневую причину.
Неизменяемый observation packet сохраняется внутри derived repair trial packet.
Новый target передаётся гипотезе, дизайну, спецификации и кандидату. Приёмка
заново проверяет inventory, хеши всех probe-зависимостей, повторяемость трассы,
достижимость выбранной функции и её собственный исходник. Разрешена замена только
этой функции; исходные тесты и другие файлы остаются неизменными.
Targeted replay и полный native regression остаются разными обязательствами.

Доказательства текущего этапа: `artifacts/role_scope_20260923/`.
Сквозные scripted-тесты покрывают generator callback и обычную функцию в другом
модуле: Analyzer → Architect → SpecWriter → candidate → native → final reviewer.
Это проверка инженерного контракта, не оценка самостоятельности модели.
Живой известный public formatter case запускается по сохранённому protocol.json:
максимум 3 HTTP-запроса, без fallback/форматных/смысловых повторов COS, резерв
802368 с учётом максимум 9 отправок GeminiVM. Реальный расход Web неизвестен;
резерв не является гарантированным расходом провайдера.

Первоначальная попытка использовать synthetic composition test дала partial
intake: локальный import API не был связан текущим static binder. Модель не
вызывалась. Для измерения выбран существующий upstream regression test #153,
где import и observed API подтверждаются binder и двумя native повторениями.
Исходные тесты не менялись. Это ограничение intake остаётся отдельным backlog.

Живой прогон: три HTTP-запроса, 927,937с, actual usage unknown.
Модель самостоятельно выбрала `visit_Tuple` в другом модуле (130,296с), затем
вернула причинную гипотезу и дизайн (199,036с). Третий запрос, генерация патча,
завершился HTTP503 provider_error через595,112с. Патч не получен, native-приёмки
модельного ремонта нет. COS сохранила controlled_stop и request_rework.
GeminiVM и шлюз в этом этапе не изменялись; дополнительных запросов нет.

Дизайн предложил безусловно заменить обработчик tuple на `_fix_tuple` при
confidence0,98. Отдельная **реализация этого предложения ассистентом** дала
128 passed /6 failed /1 xfailed при неизменных135 collected. Исходные7 failures
устранены, но появились6 других регрессий. Это доказательство недостаточности
сохранения поведения в предложенном дизайне, не результат модельного патча.
Receipts: `live-summary.json`, `calls.json`, `role-run.json`, `design-audit.json`.

Разбор входа обнаружил общий пропуск dependency context: функции, переданные
как значения (`partial(callback, ...)`, `return callback`), не включались без
прямого вызова. `runtime/upstream_dependency_context.py` теперь сохраняет такие
локальные/импортированные объявления и один дополнительный локальный helper.
Лимиты7000 символов/12 declarations и хеши сохраняются; unresolved/omitted
явные, статическая ссылка не доказывает исполнение. На известном кейсе контекст
теперь содержит оба callback и `_find_tuple`; новый модельный прогон не выполнен.
Проверки общего механизма используют другие имена и отдельный маленький проект.

По ролям: Analyzer получил рабочий source-bound переход между модулями и выбрал
нужную функцию в известном кейсе. Architect передал диагноз, но предложил
регрессивный дизайн. SpecWriter сохраняет target/исходный failure/условия приёмки
в сквозных scripted-проверках; достаточность его требований для самостоятельного
ремонта этим живым прогоном не подтверждена. Один запрос объединял гипотезу и
дизайн, не три независимых вызова ролей. Новых числовых уровней и9.7+ нет.
