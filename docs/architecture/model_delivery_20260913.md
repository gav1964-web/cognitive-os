# Доставка проверенного модельного кандидата, 13 сентября 2026

Добавлена передача точных байтов выбранного модельного вмешательства через
SpecWriter, ImplementationPlan, Programmer executor, native regression и финальный
Reviewer. Учебный KB-рецепт для этого пути не требуется. Исходный проект сохраняется.

## Контракт

В существующем модельном comparator `run_sandbox_experiment=True` вместе с
`authorize_training_replay=True` разрешает доставку в копию после единственного
поддержанного вмешательства. Без запроса исполнения остаётся прежний trial-only
режим. Неоднозначный/неподдержанный набор не получает delivery contract.
`task_contract` в модельном маршруте пока явно отклоняется; прежний учебный ремонт
с требованиями сохраняет свой контракт.

`upstream_model_delivery.v1` содержит полный проверенный replacement module,
candidate ID, packet/comparison/source/patched inventory digests и authority
`explicit_model_candidate_replay`. Материализация использует сохранённую строку,
записанную теми же UTF-8 байтами. AST editor используется для повторной проверки
соответствия структурированному предложению; его результат не заменяет сохранённый
patch. Несовпадение байтов или хеша прекращает исполнение.

Spec и Plan должны сохранять одинаковые ticket, comparison, packet и scope.
Executor проверяет актуальность всего source inventory, повторно проверяет native
TestPlan, создаёт новую копию и сверяет её с уже проверенным patched inventory.
Модельный ticket не может быть переписан в учебный operator ID. Отсутствие ticket
в модельном сравнении, удаление comparison/authority, изменение тестового packet
или source блокируют путь. Runtime digests обеспечивают согласованность; они не
являются удостоверением личности провайдера или криптографическим разрешением.

Для этого пути отключены дополнительные модельные стратегии и автоматические
repair attempts, включая случай явно включённого executor LLM. Отказ не передаёт
задание обычному генератору. Новое исправление требует нового comparison.
Сохраняются существующие запрет source apply и проверки scope/acceptance/stubs.
Полная native suite выполняется отдельно от исходных failure tests, после неё
Reviewer проверяет исходник копии и совпадение с выбранным вмешательством.
Зелёный целевой тест не перекрывает провал suite или финального review.

Оба режима предназначены для доверенного development-кода в subprocess-копиях,
а не для OS isolation произвольного враждебного кода. Generic requested changes,
произвольные многофайловые patch и самостоятельное доказательство причины сюда
не добавлены.

## Проверка

Ассистентская synthetic-фикстура содержит `invert(bool)` и два native-теста.
Первоначальный код возвращает входное truth value. Скриптованный provider предлагает
его инверсию: целевой replay проходит, полная suite даёт **2 passed**, итоговая
цепочка — `experiment_validated`, финальный Reviewer — `approve`.
Выбранный patch и исполняемая копия совпадают по байтам и inventory; исходник сохранён.

Контрольный кандидат корректен только для `False`: целевой тест проходит, полная
suite выявляет неверный `True`, Reviewer отклоняет результат, память `not_promoted`.
Проверены переподписанные подмены ticket, другое происхождение/оператор, отсутствие
provenance, удалённые authority/comparison, устаревший исходник, изменённый TestPlan
и подстановка другого зелёного patched inventory. Проверяется отсутствие новых
LLM-вызовов в executor. Сам provider во всех этих проверках скриптованный.

Первый отрицательный тест ожидал неверное имя статуса `failed`; реальный native
runner вернул `test_failed`, цепочка уже отклонила результат. Исправлено ожидание
теста, предыдущий receipt сохранён. Поведение native runner не менялось.

Профильные receipts: `artifacts/verification/model_delivery_v3_20260913.xml`,
`artifacts/verification/model_delivery_v4_20260913.xml`. Финальный снимок исходников,
регрессии и 400-line gate: `artifacts/verification/development_stage_model_delivery_20260913.json`.
Архитектурный checkpoint: `artifacts/verification/canonical_model_delivery_20260913.json`.

Увеличившийся executor приведён к лимиту обычным рефакторингом: создание снимка
writable-файлов и выбор их списка перенесены в `programmer_source_snapshot.py`,
старые импорты сохранены. Логика выбора/копирования файлов не менялась.
