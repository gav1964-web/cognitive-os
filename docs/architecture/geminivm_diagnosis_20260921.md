# GeminiVM: выбранный режим, диагностика и ограниченный прогон

21 сентября 2026. Принятый план: подтвердить выбранную модель, сохранить ошибки
через шлюз, отделить недоступность от качества COS и выполнить до четырёх
обращений к модели.

## Результат

В меню браузера первоначально выбрана **3.8 Flash**. Оператор переключил на
**3.1 Pro**. После перехода в новый чат режим Pro сохранился. API-имя gemini-web
само модель не переключает. Автоматическая проверка подтверждает видимую метку
Pro; точная версия3.1 установлена по меню, а не аттестуется короткой меткой.

| Проверка на Pro | Результат | Полный цикл |
|---|---|---:|
| Короткий контроль JSON | Точное `{"ok": true}` |112,30с|
| Три варианта Python AST | Все3 ответа совпали с независимым ast.parse/ast.dump |118,91с|
| Исходная полная задача add-trailing-comma | Содержательный JSON, контракт гипотезы принят без ошибок |169,73с|

Сообщения полной задачи посимвольно совпадают с прежним запросом, на который
Flash дважды ответил service_error. Pro объяснил превращение сгруппированного
элемента в одноэлементный вложенный tuple и предложил проверять границы tuple.
Это **accepted_hypothesis_only**: код ремонта не запрашивался, native regression
кандидата не выполнялась, баллы ролей не повышались. Confidence0.95 в ответе —
самооценка модели, не внешняя оценка качества.

Переход на проверенный Pro дал рабочий результат в этом прогоне. Он не доказывает,
что единственной причиной прежней ошибки был Flash: состояние сервиса во времени
не контролировалось. Изменение упаковки SYSTEM/USER не понадобилось; оно не
выполнялось. Длительность включает SSH/X11, проверки и копирование ответа: для
контроля от отправки до извлечения прошло около23с, для полной задачи —75с.

## Исправленные инженерные ошибки

- GeminiVM проверяет калиброванную метку модели до ввода и перед Enter. Неверная,
  неизвестная или неоднозначная метка даёт model_mismatch. В журнале сохраняется
  observed label. Автоматического выбора произвольного режима нет.
- Во время этой разработки моя первоначальная проверка дважды ложно отклонила
  Pro до отправки: кнопка смещается на42px при появлении Send, а при длинном поле
  меняется сглаживание текста. Добавлены явное смещение и точный второй эталон.
  Порог0.007 не увеличивался. Проверяются обе реальные формы Pro, отказ для Flash
  и пустого/неизвестного изображения. Ошибочные попытки сохранены.
- Шлюз передаёт code, provider, request_id и ограниченные provider_diagnostics:
  run_id, transport_status, response_status, retry_count, browser_model. Сырое
  тело ошибки не переносится. Учтено разворачивание error-объекта SDK.
- Кэш GeminiVM в5 отключён: общий alias не доказывает текущую модель браузера.
  Иначе кэш мог бы обойти новую проверку.
- Новый явно выбираемый профиль geminivm_resilient: GeminiVM → DeepSeek v3.2 →
  GigaChat-2-Pro, максимум3 маршрута, cooldown300с. Отказ и пропуск недоступного
  кандидата подтверждены offline-тестом. Замеров резервных моделей не было.
  Явный geminivm/gemini-web в диагностике не использует fallback.
- COS сохраняет ограниченную диагностику, прекращает семантические повторы с
  provider_unavailable/quality_evaluation=not_evaluated и оставляет
  pending-inference.json с сообщениями, задачей и digest исходников. Продолжение
  требует повторной проверки источника и бюджета. Доступность не считается
  отрицательной оценкой качества. Общий код не содержит ветки под GeminiVM.

SDK retries0, внутренние service_error retries0. Таймауты остались1200с у
провайдера и1800с у шлюза. Автозапуск8002 сохранился и снова сработал перед
повтором полной задачи.
