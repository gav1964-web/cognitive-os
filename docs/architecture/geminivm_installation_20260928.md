# GeminiVM: патч COS установлен и проверен на живом ответе

28 сентября2026. Продолжение прежней серии с общим пределом6млн.

## Что установлено

COS объединила два ранее одобренных этапа: строгое сравнение полного ответа и
структурное сопоставление HTML/clipboard. Между этапами добавлена ровно одна
проверенная JSON-fixture настоящего захвата; остальные исходные хеши совпадают.
Новая общая точка `runtime.feature_target_delivery.deliver_to_target` повторно
проверяет checkpoint и точные байты, исполняет объединённую приёмку, затем вызывает
транзакцию COS с backup и откатом при сбое. Авторство production и acceptance
GeminiVM — COS; ассистент написал общий механизм доставки и внешние драйверы.
Специальных веток по GeminiVM в runtime нет.

В рабочий `F:/ubuntu/test/GeminiVM` перенесены13 файлов: два production-модуля,
десять тестовых файлов и одна data-fixture. Из прежних66 исходников изменён только
`geminivm/same_chat_followup.py`, остальные добавлены. Локальные настройки и
журналы не входили в перенос. Резервная копия изменённого исходника находится в
`target-installation/backup`; новым файлам соответствует явный список установки.
Конфликт нового пути или изменение выбранной зависимости останавливают запись.

Сборка до установки и установка повторно прошли **77/77** общей приёмки.
После установки весь собственный набор GeminiVM прошёл **533/533**, без пропусков.
Прежние551 тест включали18 внешних проверок;533 — именно набор в рабочем проекте,
это не падение числа успешных тестов и не исключение дефектов из прежней проверки.
Установленные байты сверены с конечным inventory после живого прогона.

Перезапущен только подтверждённый HTTP-процесс8002, под блокировкой свободного
desktop, штатным скрытым launcher шлюза5. Firefox и VM не перезапускались.
Готовность подтверждена `/v1/models`:flash,pro,gemini-web.

## Живая проверка

Первый запрос COS через5 остановился на SSH banner timeout за10.4секунды.
Журнал содержит только `export DISPLAY=:99; true`; ввода и отправки в Gemini
не было. Отдельный read-only SSH `true` затем прошёл за1.344секунды, с прежней
строгой проверкой ключа. Конфигурация таймаутов на диске не менялась.

После этого выполнен один повтор. Реальный **GeminiVM Pro** вернул за **98.3с**
ожидаемый JSON: отрицательное число, ноль, положительное число и строку Python
с `!=`, `<=`, отступом и переносами. Сравнение с заранее заданным объектом прошло.
Gateway сообщил cache_hit:false и единственную модель geminivm/pro;
провайдер подтвердил browser_model:Pro, response_status:normal, retry_count:0,
continuation_count:0. Это транспортная проверка небольшого задания, не оценка
качества программирования модели.

Дополнительно без нового чата/запроса прочитан текущий настоящий HTML страницы.
Установленная `project_responses` выделила один ответ; `_same_complete_text`
сопоставила его целиком с выданным ответом. Receipt:installed-binding-observation.
Тем самым новый механизм проверен и на свежих реальных данных, не только на
предыдущей сохранённой fixture. Внутренняя ошибка Gemini в успешном запросе
**не возникла**: автоматический путь ошибки → `?` → новый ответ живьём не проверен.
Нельзя объявлять провайдер устойчивым или искусственно считать обычный ответ
срабатыванием восстановления.
