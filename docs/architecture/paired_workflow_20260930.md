# Сравнение полного и условного аудита COS, 30 сентября 2026

Протокол зафиксирован до модельных вызовов в
`artifacts/paired_workflow_20260930/protocol.json`; исходная версия сохранена в
`cos-before`, сравниваемая версия — в `cos` с inventory и seal.

Три известные диагностические задачи: неизменность контекста, цепочки алиасов,
многовитковые дуги. Для каждой два варианта, одинаковые исходники/цель/внешняя
приёмка, Luna, 350000 новых токенов, 18 вызовов и 4 цикла. Порядок вариантов
чередуется. Это сравнение механизмов на знакомых задачах, не новый holdout.
Общий лимит этапа 3000000 новых токенов; исторические 5373647 сохранены.
900000 зарезервированы на полный VR с исходным набором тестов и DWG/PDF.

API `run_quality_development(audit_mode=...)` по умолчанию сохраняет `always`.
Экспериментальный `on_feedback` включает дополнительные модельные аудиты при
замечаниях допуска/исполнения/review, изменении нескольких production-путей
или наличии сохранённой кампании контрпримеров. Расписание принадлежит
`development_quality.audit_schedule.v1`; runtime журналирует каждое решение.
Пропуск не считается одобрением. Native baseline/candidate, ограничения записи,
проверка исходников/неизменности тестов и Reviewer остаются обязательными.
Текущий режим предназначен для диагностического сравнения, не сертификации.

Переиспользование принятых метаданных применяется одинаково в обоих вариантах.
Старые проверки не переписываются ради прохождения эксперимента. Все остановки
и неуспешные вызовы входят в результат. COS не ремонтируется между парными
запусками. Естественный кэш шлюза сохраняется; фактический новый расход и
логический объём запросов учитываются отдельно. Холодная стоимость не доказана.

Основной показатель — полное завершение без вмешательства ассистента и с
независимой внешней приёмкой. Далее — регрессии, полная стоимость и время.
Ложное принятие по внешним тестам исключает вариант из выбора. При равенстве
результатов предпочтителен меньший известный логический расход; при неопределённости
остаётся стандартный полный аудит. Глобальный default этим опытом не меняется.

## Полный проект и подготовка среды

Копия VR содержит89 доступных исходных/тестовых/документационных файлов и78 файлов
данных:67DWG,6PDF и5 подготовленных моделей/метаданных, нужных штатным server-тестам.
Первый baseline:106passed,4failed,1skipped. Четыре отказа вызваны тем, что ассистент
не скопировал требуемые готовые модели. После дополнения данных, без правки кода,
повторный полный baseline:110passed,1skipped,41subtests. Первый отчёт сохранён.
Исходные DWG/PDF и оригинальный проект не менялись.

Первый live trial на полной копии остановился до Programmer:15 вызовов,
210825 токенов, feature_repeated_request_without_progress. Нельзя считать его
автономным успехом. Отклонялась правильная полная ссылка на существующий метод
GeoJsonExportTests: case_plan терял класс при построении inventory, а контрасты
понимали только классы с префиксом Test. Это подтверждённая ошибка COS.

Общий ремонт development_quality0.1.19 сохраняет квалифицированные имена классов,
поддерживает pytest-классы и статически определимые наследники unittest.TestCase,
включая алиасы импортов и локальное наследование. Отсутствующие исходники,
невыбранные regressions и подмена класса по-прежнему отклоняются. Native collection
остаётся окончательной проверкой.94 профильных теста прошли, последний оплаченный
ответ COS прошёл исправленный структурный допуск без редактирования его содержимого.

Продолжение отделено от первого trial: full-resume, одно вмешательство ассистента
в COS, неизменные цель/проект/оплаченный черновик. Суммарный предел обоих полных
запусков900000, до18 новых вызовов. Парные результаты не переписываются.

Эксперимент использует прямой Python API. В первом запечатанном снимке индекс
plugin hash ещё не включал новый файл расписания; этот loader-путь не измерялся.
В рабочем дереве регистрация обновлена и проверена, исправленный снимок имеет
актуальную регистрацию. Ни исходный снимок, ни его результаты не изменены.

## Завершение полного VR

Первое продолжение после исправления class nodeids:290572 токена,15 вызовов,
quality_cycle_limit. Аудитор требовал прогноз для выбранного старого regression,
тогда как Writer и структурный контракт запрещали такую строку. В0.1.20 инструкция
аудитора явно согласована с runtime: baseline_expectations относится только к
specification.tests (включая принятые новые тесты); исходные regression_tests
проходят отдельный all-green baseline. Новый native regression проверяет именно
это разделение на настоящем методе unittest-класса. Ни один gate не отключён.

Сохранённая старая обратная связь ещё несколько итераций мешала исправлению;
это отдельная задача policy-versioned-audit-feedback. Запланированный запасной
перезапуск с нуля НЕ запускался: продолжение всё-таки завершилось.

Финальное продолжение:191616 токенов,12 вызовов, полный цикл verified/goal_complete,
Reviewer approve, Challenger passed, поставка в копию verified. COS сама заменила
однократное прибавление360 на модуль360 с отдельной обработкой нулевого остатка.
Ассистент не писал production-патч или приёмочные тесты VR.

Результат:12 native-проверок приёмки,8/8 внешних, полный штатный набор **121passed,
1skipped,41subtests**, новых регрессий0. Baseline был110passed/1skipped; добавлено11
тестов COS, старый пропуск сохранён. Сравнение JUnit нормализует только временный
родительский package-префикс перед tests.; класс/метод/параметры не меняются,
коллизии запрещены. Исходные JUnit сохраняются. Все CAD/PDF inputs и оригиналы
проектов неизменны. Артефакт поставки:
`artifacts/paired_workflow_20260930/full-resume-policy/delivery/project`.

Это успешная интеграция известной ограниченной задачи в полный проект ПОСЛЕ
двух общих исправлений COS, а не автономный первый успех. Испытание через Python
API не сертифицирует установленную службу и не проверяет весь спектр задач DWG.
