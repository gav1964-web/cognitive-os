# Ultra: формат кода и сохранение поведения — 24 сентября 2026

Продолжение [проверки ремонта силами COS](analyzer_reading_20260924.md).
Рабочий production-код не изменён; модельный ответ не исправлялся ассистентом.
Артефакты: `artifacts/ultra_code_format_20260924/`; итог — `verification.json`.

До запросов зафиксированы тот же candidate prompt, исходник, дизайн Ultra,
схема локальной проверки и приёмка. Два запроса, output cap 32768, timeout180,
резерв178304; повторов по формату/смыслу нет. Меняется только response_format:
native json_schema → text. В обоих вариантах COS требует целый JSON по прежней
схеме и применяет прежние проверки Python-кандидата.

## Результат

Первый запрос вернул прежние заголовки функций **из кэша шлюза**, поэтому это
не новый независимый ответ Ultra. Gateway сообщил cache_hit=true и usage0.
BudgetedChat считает любой нулевой usage неизвестным; после проверки ветки
раннего возврата шлюза, совпадения response hash и нулевых полей учёт этого
конкретного запроса разрешён как ноль новых generation tokens. Исходная
телеметрия с usage_known=false сохранена; основание и hash кода шлюза —
`cache-audit.json`. Это локальное свидетельство, не provider billing attestation.
Внутренние лимиты или повторы не обходились, production-учётчик не изменялся.

В режиме text Ultra вернула **полный модуль с телом функции**, 1166 completion
tokens, finish_reason=stop. Строгий JSON/schema прошёл; контракт одной функции
нарушен, COS вернула `replacement_must_be_single_function`. Ранее native schema
дала только заголовки. Значит, смена формата на этом запросе сопровождалась
появлением тела; из одного нового ответа и исторического контроля нельзя
сделать вывод об универсальной причине или автоматически менять профиль.

После чтения всего модуля ассистент проверил его точные байты в изолированной
копии **как отклонённый диагностический образец**. Код не извлекался из модуля,
не дополнялся и не принимался в обход function-контракта. Замороженные 13 тестов
и 5 reviewer cases одинаковы для baseline и кандидата:

| Проверка | Baseline | Точный модуль Ultra |
|---|---:|---:|
| Успешные тесты | 11 | 12 |
| Падающие тесты | 7 | 6 |
| Ранее падавшие случаи, исправленные кандидатом | — | 7 |
| Ранее успешные случаи, сломанные кандидатом | — | 6 |

Кандидат устраняет ложную ambiguity при атрибутах/индексах, но теряет настоящие
bindings в starred, вложенных и смешанных присваиваниях. Это обнаруженные
регрессии, а не предположение. Уточнение25 сентября: прежнее замечание о замене
разделителя excerpt было ошибкой чтения экранированного JSON. AST обоих исходников
содержит LF (код10), разделитель не изменялся; шесть реальных регрессий сохраняются.
Расширять серию после двух запросов не стали.

Один свежий вызов Ultra: **4846 reported tokens**, latency21.155s,
cache_hit=false, provider retry_count0. Второй HTTP-запрос обслужен кэшем.
Не смешивать эти цифры с 20776 токенами предыдущего этапа.
Принятых патчей0; ручных production-патчей0. Основные профили и баллы ролей прежние.

## Дальше

Препятствие не сводится к отсутствию тела функции: после его появления проявилась
ошибка алгоритма, предсказанная оговоркой в дизайне Ultra. Следующий ремонт COS
должен использовать её существующий preservation-контекст и фактические
контрпримеры для **пересмотра дизайна**, а не только синтаксическую обратную связь.
Не подсказывать готовую реализацию и не принимать прохождение одного исходного
сбоя за успех. Установка возможна только после неизменной полной приёмки и
сфокусированной регрессии; при повторном отказе — сохранить отрицательный результат.

Пять прежних reviewer cases сохранены без изменения также в
`tests/runtime/test_failure_test_context_preservation.py`, чтобы найденные
регрессии оставались в обычной проверке проекта. Семь strict xfail исходного
дефекта остаются открытыми. Новая проверка не означает завершённого ремонта.
