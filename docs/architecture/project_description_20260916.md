# Описание проекта для человека — 16 сентября 2026

## Проблема и граница

В сохранённом анализе map технические признаки Flask/Leaflet не превратились в
понятное описание продукта. Назначение загрязнил HTML-фрагмент, сценарии пришли
из ошибочного async-worker профиля, текст app.py превысил лимит чтения. L4
перенёс ошибочную интерпретацию. Его архитектурный контракт на 1200 символов
не предназначен для полноценного описания пользовательских возможностей.

Добавлен явный маршрут `tools/describe_project.py`. Существующий архитектурный
маршрут и классификаторы не переписаны; новое описание пока не подменяет
автоматически их входы. Это отдельная задача после проверки контракта.

## Владение и исполнение

`plugins/project_description` 0.1.0 владеет отбором контекста, сокращением исходников,
локальной KB с инструкциями объяснения и проверки. Capability read-only, без
сетевых эффектов. Зарегистрированная identity проверяется общим loader.

`runtime/project_description.py` организует два модельных запроса: черновик,
затем отдельную фактическую проверку. Между ними и после них проверяются хеши
прочитанных исходников. Неуспешный review не публикует черновик. Configured
DeepSeek/GigaChat failover сохраняется; telemetry содержит попытки и usage.
Это два запроса модели, а не бесплатная детерминированная обработка.

Контракт разделяет purpose, scenarios, data_flow, unknowns, confidence.
Это описание продукта; свободный технический аудит ограничений в контракт не входит.
Каждое модельное утверждение ссылается на реальные ID исходников. Проверка ID
не доказывает семантическую истинность. Факты владельца выводятся дословно
отдельным блоком и вообще не передаются модели; owner IDs недоступны модели.
Индекс буквальных маршрутов, glob-форматов,
аргументов CLI и видимых UI-элементов помогает сохранить пользовательские сценарии.
Фактический review также остаётся вероятностным; требуется отдельная оценка.

Отбор не содержит названий map, его города, путей или конкретных форматов.
Приоритет — известные имена entrypoints и прямо упомянутые локальные скрипты.
Крупные Python-файлы представлены заголовком, видимым UI-текстом, фрагментами
функций и синтаксическими признаками входных форматов/условий. Перед нарезкой
сокращаются большие строковые литералы: это позволяет сохранить исполняемые
ветви целиком у крупных файлов со встроенным HTML. При доступном entrypoint
README даёт только краткое заявленное назначение. Код не исполняется.
Полные байтовые дубликаты отмечаются без угадывания имени установочной папки.
Это не решение задачи выбора активного корня. Пропуски и сокращения явные;
окружение, приватная конфигурация и типовые литералы credentials исключаются.

## Проверка на map

Согласованный с владельцем эталон сохранён отдельно и не передаётся модели.
В первых экспериментах передавался только его факт: при недоступности внешней LLM
импорт продолжается с меньшей точностью. В итоговом маршруте этот факт обрабатывается
детерминированно, без LLM. Основания модели — текущие исходники и обзор из README.

Первые два новых описания не приняты: модель смешала устаревшую документацию
с реализацией. Они сохранены вместе с замечаниями, а не заменены успешным ответом.
Третья попытка: DeepSeek timeout, ответ GigaChat с вымышленными evidence IDs
отклонён контрактом. Четвёртая показала, что один LLM-review ещё не устраняет
ошибки при неудачно сокращённом коде и доминировании README. Полные receipts и дальнейший результат находятся в
`artifacts/map_description_20260916/improved/`; итоговый audit указывает принятый
ответ, критерии, ограничения и все расходы. Исходники map не изменяются.

Это знакомый проект и assisted iteration, не independent holdout и не 9.7.
Отдельный invoice CLI fixture проверяет отсутствие доменных подстановок;
тесты контракта не измеряют качество живой модели на любых проектах.

## Итог измерения

Принят с замечаниями `artifacts/map_description_20260916/improved/product_brief.json`
и соответствующий Markdown. Он описывает назначение, слои, поиск, фильтры,
подробности событий, непривязанные записи, импорт со статусом и экспорт.
Сохраняются многословность, неточное слово «таблица» для списка непривязанных
событий и отсутствие явного упоминания source-file provenance в описании.
Это не полное равенство качеству внешнего ассистента.

Сравнение на идентичном исходном запросе показало лучший результат маршрута
`deepseek/deepseek-v3.2`, чем `deepseek/deepseek-chat`, на этом знакомом проекте.
Для компетенции добавлен отдельный профиль с v3.2/120 seconds; основной L4.5
и его failover остаются прежними. Это выбор по данному измерению, не общий рейтинг.
Синтетический invoice CLI также описан живой моделью корректно (CSV → суммы
по клиентам → JSON), без предметных подстановок map. Он не независимый holdout.

Успешный map-прогон: два запроса, 62380 сообщённых токенов, около 80 секунд.
Все эксперименты этапа: 407318 сообщённых токенов; расход запроса с timeout
неизвестен, резерв сообщил 0, один ответ получен из кеша шлюза. Это сумма usage,
не полный подтверждённый биллинг. Расход существенно выше старого краткого ответа;
дальнейшее сокращение контекста допустимо только с проверкой сохранения качества.

Следующий шаг: независимые проверки описаний проектов другого назначения;
затем явный handoff проверенного описания в Analyzer/Architect без повышения
авторитетности неподтверждённых утверждений модели.
