## Что представляет собой map

По итоговому описанию COS это локальная веб-карта Курска/окрестностей с дорожной
основой, поиском, инцидентами и дополнительными слоями: филиалы/банкоматы,
энергообъекты, АЗС. Инциденты отбираются по датам и группам; непривязанные записи
доступны отдельно. Экспорт — JSON/CSV, только привязанные события. Сервер читает
локальные JSON; дороги выбирает по масштабу и видимой области.

Импорт запускается из интерфейса, обрабатывает RTF из `indoc`, извлекает события
и сопоставляет места с локальным справочником. LLM используется для части строк;
при её отключении/недоступности остаётся разбор по правилам. После успешного
импорта приложение перечитывает `incidents.json`. Снижение точности без LLM —
ранее сообщённое владельцем свойство; сравнительная точность здесь не измерялась.
Полная работа всех браузерных сценариев без сети не проверена.

## Что фактически проверено

Диагностический Python-код написала COS/Luna. После проверки допустимости COS
запустила точный код в копии исходников с двумя дополнительными JSON-файлами,
общим размером около92.5МБ. Flask test_client вызывал только GET, без запуска
импорта, внешних запросов, сервера и изменения данных. Сохранялись количества
и формы ответов, не содержимое событий.

| Наблюдение | Результат |
|---|---|
| GET-запросы, включая разные параметры |20 ответов HTTP200 |
| Дорожная карта, zoom10 |8791 объект |
| Филиалы/банкоматы |142 объекта, из них31 филиал |
| Энергообъекты / АЗС |94 /97 объектов |
| Поиск |20 результатов на широком запросе, ограничение20 соблюдено |

Отсутствие выбранных групп приводит к пустым ответам инцидентов и экспорта;
это видимое условие кода, а не установленная ошибка. Проверки даты и лимита
непривязанных записей частично прошли на пустых результатах и не доказывают
правильности фильтрации на границах.200 не является доказательством семантики,
браузерного отображения или приёмкой всего приложения. Числовые оценки ролей
не пересчитывались.

## Что показал эксперимент о COS

Первый черновик Luna содержательно описал проект. Штатный review с ограничением
32к символов всего и4к на исходник потерял поиск, экспорт, часть слоёв и связь
импорта с обновлением приложения. Review сам выбрал недостаточные диапазоны.
Такой результат сохранён как неудачный, хотя формально имел status=described.

В плагине описания добавлен общий **opt-in** профиль expanded:96к символов
контекста и32к на обычный исходник; прежний профиль остаётся по умолчанию.
Повторный review того же сохранённого черновика запросил подходящие участки,
сохранил функции и уточнил важное условие: экспорт только привязанных событий.
Никаких подсказок по домену map в runtime/KB не добавлено. Это локальный успех
управления контекстом, не подтверждение универсальной правильности описаний.

Диагностика обнаружила и ошибку транспорта COS на Windows: изолированный Python
игнорирует PYTHONUTF8, и кириллица в JSON могла повреждаться при чтении stdout.
Результат теперь передаётся ASCII-escaped JSON и восстанавливается без потерь.
Тот же модельный скрипт повторён локально без inference; исходный receipt сохранён.

   Текущий smoke даёт основу, но не покрывает эти свойства полностью.
