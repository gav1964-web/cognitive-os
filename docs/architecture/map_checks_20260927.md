# map / COS Luna: проверка трёх предложенных направлений

27 сентября 2026. Продолжение [анализа map](map_luna_20260926.md) по поручению
владельца. COS написала и исправила диагностические скрипты; ассистент передавал
исходники, наблюдения и ошибки исполнения, проверял допустимость и результаты.
Предметный код map и его рабочие данные не менялись. Специализации runtime/KB
под map нет; новые файлы этого этапа — артефакты опыта и документация.

## Результат

| Направление | Проверенное поведение |
|---|---|
| Браузер с блокировкой внешней сети | Загрузка карты/событий/слоёв, поиск с результатом, выбор группы и всех групп, выключение/включение энергообъектов и АЗС |
| Импорт без LLM | Настоящие parser и CLI `--no-llm` на синтетических RTF: два события, одно привязанное и одно непривязанное; повторный импорт и штатный reload дают три события |
| Фильтры и экспорт | Непустые JSON и CSV: по две записи, точное совпадение с независимой выборкой; группа, включённые границы дня и bbox |

Итог: **17/17 backend-проверок и 12/12 браузерных проверок**. В число проверок
входят служебные условия (HTTP, сохранение скриншота, отсутствие ошибок), а не
29 независимых пользовательских сценариев. JS-ошибок, внешних запросов, нарушений
политики GET и неуспешных HTTP-запросов в завершённом браузерном прогоне — ноль.
Скриншот просмотрен ассистентом: видны карта, результаты поиска и панели слоёв.
Хеши 45 исходных текстовых файлов и дополнительных входов исходника/копии
неизменны; ранее существовавшие пользовательские изменения сохранены.

Браузерные запросы обслуживались настоящим Flask test_client по виртуальному
локальному origin. Это не проверка настоящего HTTP-сервера или установщика и не
изоляция сети всего процесса ОС. Импорт проверен через CLI и reload на временных
фикстурах, без нажатия кнопки импорта в рабочем проекте. JSON/CSV проверены через
backend, без браузерного скачивания. Сравнение точности rules/LLM, все варианты
RTF, диапазоны картографических масштабов и исчерпывающие комбинации фильтров
не проверялись. Дефектов map в выполненных сценариях не обнаружено.

## Что получилось и где COS ошиблась

Первая версия backend дала 13/16: три ошибки были в формате самих сравнений
(число против словаря; дата против списка). Первое исполнение браузера не
загрузило страницу: COS передала строковый Flask status вместо status_code.
Ассистент вернул native-наблюдения и сигнатуры установленного Playwright; COS
исправила представление ожиданий, адаптер, ожидание асинхронных ответов и проверку
границ в реально возвращённых данных. Ожидаемые значения не ослаблялись.

В исправлении COS случайно потеряла каталог в пути Chromium. После передачи
проверенного пути следующий ответ изменил только executable_path (diff сохранён
в истории инструментов, исходные предложения сохранены). Затем точный модельный
код прошёл проверки. Ассистент не редактировал предметный диагностический код.
Это полезный перенос на другой проект с обратной связью, но пока не полностью
автономное тестирование: помощь в разборе ошибок была существенной. Числовые
оценки Analyzer/Architect/SpecWriter не повышаются на основании этого опыта.

разработки должен исходить из конкретного пользовательского изменения либо
воспроизводимого дефекта. Продолжать произвольные испытания ради количества
шагов или приписывать диагностике рост балла ролей оснований нет.
