## Исторический незавершённый срез 21 сентября

Реализован только механизм политики `GeminiVM/geminivm/cleanup_policy.py`.
Он требует полный, явно проверенный снимок ID в порядке от старых к новым,
планирует удаление при100+, закрепляет сохраняемые15 перед первым удалением,
проверяет результат каждого удаления и восстанавливает прерванную транзакцию.
Сохраняемые ID не меняются после перестановки списка. При потере защищённого ID,
неполном снимке, дубликатах или изменении browser scope операция останавливается.
Есть dry-run без записи защищённого набора. Модуль ещё не подключён к Provider.ask,
CLI или фоновому обслуживанию: автоматическая очистка **не реализована целиком**.
