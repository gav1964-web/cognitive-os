# Проверка установленной службы COS — 28.09.2026

Пользователь установил пакет от имени администратора. Прямая проверка SCM
подтвердила `CognitiveOSWorker`, `Running`, `Auto`, учётную запись
`NT SERVICE\CognitiveOSWorker`. Хеши706 установленных файлов совпали с manifest.

## Подтверждено

- Настоящее задание исполнено под ожидаемым service SID.
- 10/10 проверок отказа доступа: чтение/запись тестового key, policy, state
  контроллера; запись request и worker config; права подмены deployment namespace.
- Отдельная копия COS с33 локально скопированными зависимостями перепроверила
  сохранённую спецификацию. Analyzer, Architect, SpecWriter и frozen tests
  сохранены; исполнение дошло ровно до следующего неоплаченного Programmer.
- Watchdog завершил зависшее задание; служба сохранила heartbeat и продолжила
  принимать диагностику. Захваченное задание не повторялось.

## Живой прогон не прошёл

План: та же разрешённая задача на7 выбранных файлах шлюза, Luna,
до6 новых обращений, общий предел450000 вместе с прежними53225.
Шлюз проверен штатным bootstrap **до** нового резервирования. Рабочие исходники
шлюза, VR, map и GeminiVM не менялись; checkpoint перенесён только в копию.

Контроллер получает HTTP200 от `127.0.0.1:8000/health`. Из задания службы
соединение TCP и HTTP health-check заканчиваются таймаутом. Дамп Python
показал ожидание в `socket.connect`. Причина различия пока не установлена:
это не подтверждённая ошибка модели, не доказанный дефект firewall/VPN.
Настройки сети и защиты не изменялись.

Ролевой worker записал `remote_role_gateway_not_ready` до создания FeatureChat
и нового ledger. Его процесс пришлось завершить watchdog. Платных обращений0,
нового reported usage0. Исторические53225 не переписаны. Поздний completion
проверяется отдельно от первоначального таймаута dispatch; состояние бюджета
после сверки хранится в `reconciliation.json` и `summary.json`.

Остановка/запуск через SCM текущему Alex запрещены; реальный restart службы не
проверен. Запрошенный у пользователя ручной restart впоследствии отменён, когда
сработал watchdog. Завершение диагностического процесса первоначально отклонено
автоматической проверкой из-за устаревшего PID; повтор выполнен после проверки
команды, родителя и времени создания непосредственно перед остановкой.

## Следующий ограниченный шаг

Сначала восстановить короткий health-check **из фактического worker**, затем
повторять ролевой прогон. Не выделять20 минут роли до проверки этого условия.
Сетевую причину уточнять по сравнению процесса/учётной записи/маршрута; не
отключать защиту и не расширять bind шлюза ради прохождения теста. Проверки
SCM stop/restart потребуют административного контекста. При выборе другого
способа доставки inference сохранить controller-side бюджет и закреплённый
endpoint; не подменять проверку раздельных аккаунтов запуском всех ролей у
контроллера.

Это проверка инфраструктуры, не новое независимое измерение качества первых
трёх ролей. Их оценки не повышаются. Исправлены ошибки подготовительного стенда
(необязательный win32file, void-return snapshot, отсутствующий import в print);
изменений алгоритмов COS по результатам этого прогона пока нет.
