# Прогон Cognitive OS на map — 13 сентября 2026

Проверен `F:/ubuntu/test/map`. Первая попытка текущего COS сохранена до диагностики
ассистента. Проект уже использовался в прежних migration trials; этот запуск не
является независимым holdout и не повышает оценки ролей до 9.7+.

## Что выполнилось

Исходный development-прогон остановил ролевой handoff на `research_required`:
распознавание ошибочно выбрало `async_worker_scheduler` с confidence 0.63,
дерево с `map_install_package` получило `dirty_portfolio`. Foundation с явным
корнем `.` также остановился на выборе области. Это сохранённые неудачные попытки.

Для следующего прогона ассистент скопировал корневые Python-файлы, batch-команды,
requirements и README в `artifacts/map_assessment_20260913/active_source`.
Установочная копия, backups, окружение и наборы данных исключены явно. Это область
анализа исходников, не готовая поставка приложения. Она позволила выполнить полную
обычную ролевую цепочку с executor. Исходные файлы map сохранены: хеши контролируемых
Python/requirements/static-файлов совпали до и после.

модели и качество DeepSeek/GigaChat этим измерением не определяются.

## Внешняя проверка приложения

`test.py` и `test2.py` — диагностические скрипты SQLite/PNG, без test-функций и
assertions. Второй пишет PNG; они не запускались на исходной базе как pytest-suite.

Ассистент добавил отдельные проверки на неизменённых байтах `app.py`, Flask
test_client и маленьких искусственных GeoJSON/settlement fixtures. Без TCP,
настоящих данных и запуска `/import_indoc/start`: **18 passed, 3 failed**.
Прошли 11 read-маршрутов, поиск, CSV, фильтр bbox и обычный некорректный bbox.
Три отказа — предложенное требование отвергать `NaN`, `+Infinity`, `-Infinity`.
Сейчас `parse_bbox` возвращает их в tuple. Это найденный ассистентом пробел
валидации, не самостоятельное открытие ролевой цепочки.

Проверки не охватывают браузерное отображение карты, реальные объёмы данных,
импорт документов, внешний LLM/геокодер и гонки фонового импорта.

В корневых исходниках map: `app.py` — 1895 строк, `import_indoc.py` — 774.
Правило COS в 400 строк не применялось автоматически к внешнему проекту.

## Изменения COS по итогам этапа

- Устранён ложный верхний статус `ready_for_experiment` при handoff
  `research_required`, `controlled_stop` или `needs_replanning`. Повтор исходного
  map теперь сообщает `research_required`; неправильная классификация остаётся
  видимой и занесена в очередь.
- `upstream_call_bindings` связывает уникальные функции модуля и import aliases
  с точной source-целью. Локальное затенение, неоднозначность, star-imports,
  динамическое пространство имён и dispatch методов не дают доказанной связи.
  На map получены три статические ссылки на `parse_bbox`: обработчики карты,
  событий и экспорта. Это не полный граф вызовов и не гарантия runtime identity.
- Наблюдение о заглушке той же цели сохраняется отдельно от native failure,
  не создавая второй пустой packet. Точные повторения удаляются, разные native
  signatures/наблюдения сохраняются и не получают искусственной однозначности.

## Следующие задачи

Для map: согласовать явный контракт bbox и добавить штатную автоматическую suite;
затем проверять фильтрацию/экспорт на реальных структурах событий и состояние
импорта. После фиксации поведения разделять app.py на HTTP, GeoJSON/фильтрацию,
загрузку данных и шаблон UI; import_indoc — по разбору, LLM и импорту.

Для COS: исправить распознавание приложения и выбор активных исходников при
соседней установочной копии; проверить полноту числовых граничных условий Tester.
Новый независимый case, реальные модельные гипотезы и стоимость остаются отдельной
работой. Наличие `approve` и зелёного harness не закрывает эти вопросы.
