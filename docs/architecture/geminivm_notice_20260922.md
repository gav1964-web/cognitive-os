## Диагностика после подтверждения владельца

Восьмая и последняя HTTP-попытка пакета — `fresh-diagnostic`; сравнение всего
списка сообщений с `fresh-recovered` обязательно перед отправкой. Это тот же
публичный humanize-кейс, без новых исходников COS в запросе. Диагноз переиспользован,
кандидат запрошен один раз. Run GeminiVM `20260922T090649-7c1c1013096c`:
GENERATING09:08:06 → READY09:11:28 → controlled unknown_ui09:11:40 UTC.
Весь цикл299с, source_unchanged=true, ответа нет. Usage неизвестен.

Открытая в отдельном свёрнутом окне Multiprocess Browser Console сохранила
предупреждения CSP/загрузки/защиты от fingerprinting, но **не записала HTTP-статусы
нужного запроса**, хотя фильтры XHR/Requests были включены. Поэтому этот повтор
подтвердил воспроизводимость, но не установил сетевую причину. Выбор общей консоли
оказался недостаточным; предварительно проверялся экспорт текста, а следовало
проверить экспорт именно HTTP-записей после перехода страницы. Не считать этот
журнал доказательством таймаута/отказа сервиса Gemini.

В текущем списке процессов пользователя VM нет другой Python/Node-автоматизации
(кроме самой диагностической команды); user timers0, crontab отсутствует.
Активные расширения — компоненты Mozilla. Это проверка текущего состояния,
не доказательство отсутствия любого внешнего воздействия в прошлом.
