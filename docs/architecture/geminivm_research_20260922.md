## Контракт источников

GeminiVM с `capture_sources=true` после успешного ответа читает native Firefox
rich-text clipboard. Это Ctrl+A/Ctrl+C и системный xclip, без запросов к DOM,
JavaScript в браузере, OCR, CDP, Playwright или внутренних API Gemini.
Парсер ограничен последним `model-response`, привязывает его к скопированному
ответу и исключает sidebar, пользовательский prompt, прежние ответы.
Сбой сбора источников сохраняется отдельно и не уничтожает уже полученный ответ.

`web_evidence.v1` проходит GeminiVM `geminivm.web_evidence` → шлюз5
`provider_diagnostics.web_evidence` → telemetry COS. Поля:

| Поле | Смысл |
| --- | --- |
| capture_status | captured или unavailable; captured может иметь пустой список |
| search_usage | unknown: наличие ссылок не доказывает встроенный поиск |
| response_sha256 | Хеш точного полученного текста; COS проверяет совпадение |
| clipboard_sha256 | Хеш нативного HTML-буфера, если сбор выполнен |
| sources | Максимум8 HTTPS-ссылок, URL≤2048 и title≤300 символов |
| origin | source_panel, response_link либо response_text |

`response_text` — URL, буквально предложенный моделью, например внутри JSON;
он не выдаётся за подтверждённую поисковую цитату. Даже source_panel не
обозначается как search_used: источники могут быть связаны с ответом иначе.
Бюджет output32768 GeminiVM не умеет обеспечивать; токены не сообщает.
Шлюз теперь передаёт отсутствующий usage как null в ответах с диагностикой,
а не синтетические нули. COS сохраняет usage_reported=false и счётчики null.

## Вопрос → проверка → владелец

`runtime/role_research.py` принимает явный вопрос с role, owner,
allowed_domains и applicability={technology,version,url_prefix}. Владелец —
существующий активный плагин. Один запрос модели, без fallback/форматных retry,
максимум3 утверждения. Заданные домены и область версии модель менять не может.

COS независимо загружает предложенные страницы: только HTTPS и точный allowlist,
публичный DNS-адрес, соединение с проверенным IP и TLS-проверкой имени хоста,
не более3 перенаправлений и512000 байт на страницу. Каждый redirect проверяется
повторно; переход на иную область версии отклоняется. HTML не исполняется.
Цитата≤25 слов сопоставляется с извлечённым текстом; сохраняется хеш тела страницы.
Ссылка без найденной цитаты не становится проверенным утверждением.

`evidence_checked` означает подтверждённую цитату и допустимую URL-область
версии. Это не проверка всех семантических выводов: semantic_entailment остаётся
not_verified. Кандидат получает owner и admission=pending_owner_review;
журнал `artifacts/research/<owner>/` — инфраструктура доказательств, не общая
доменная KB. Допуск в активную KB остаётся за версионным контрактом и проверками
плагина-владельца. Этот этап не добавляет автоматическую promotion.

Операционный pipeline принимает до3 `--research-request` (по одному на роль).
Проверяются все запросы и маршруты до первого внешнего вызова. Проверенные цитаты
передаются только целевой роли в advisory_context.external_research. Analyzer
получает их в обеих стадиях, Architect/SpecWriter — в существующих advisory.
В отчёте сохраняются role_research, receipts и исходы. Внешняя документация
не определяет поведение локального проекта и не создаёт новых требований.

Есть также `tools/research_question.py` для одного вопроса и подключение к
`execute_research_plan(..., model_research_request=..., model_config=...)`.
ResearchPlan с model_web_research без явного запроса не запускает модель.
