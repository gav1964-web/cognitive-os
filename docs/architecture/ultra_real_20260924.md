# Ultra на двух реальных дефектах: 24 сентября 2026

Итог: одна полная успешная цепочка, вторая остановлена на формате SpecWriter.
Ultra остаётся кандидатом; это не основание переключать defaults или присваивать
первым трём ролям новые баллы. Сравнения с другой моделью в этой серии не было.

## Что проверялось

Два небольших дефекта действующего кода, без искусственной мутации исходников:

1. Шлюз 5 возвращает HTTP 502 для локального `bad_request` без upstream status.
   Требовалось 400 с сохранением всех остальных отображений и error envelope.
2. Standalone-клиент COS не проверяет точный тип `max_output_tokens`: True,
   дробные значения, NaN/inf могут дойти до HTTP, а строка/list/dict вызывают
   необработанный TypeError до сети. Требуется LocalInferenceError до IO;
   None и любые положительные built-in int, включая 65536, остаются допустимы.

Ассистент выбрал исходники, сформулировал контракты и написал acceptance до
inference. Это открытая инженерная проверка, не независимый holdout. Последовательно
вызывались Analyzer, Architect, SpecWriter, затем код при допуске. Предыдущие
ответы передавались следующей роли буквально, без исправляющих подсказок.
Это экспериментальные ролевые запросы через COS BudgetedChat/local_inference,
а не полный production configured_role_pipeline.

Восемь слотов, общий резерв 873216, выход 32768, timeout 300 с, temperature=0,
без повторов/fallback. Шлюз по текущему коду задаёт отсутствующий top_p=0.9.
Протокол заморожен до вызовов. Последний слот кода не использован.

## Сбой формата и дефект COS

Ultra вернула Python-литералы `None`, `True`, `False`, `float('nan')` и неверно
экранированные ключи внутри ответа, требовавшего JSON. Строгий json.loads падает
на строке 5. `_loads_json_object` в COS затем сканирует вложенные фигурные
скобки и возвращает **один пример C2** вместо всего документа. Ролевая проверка
эксперимента обнаружила отсутствие `cases/regression_scope/invariants` и остановила
цепочку. Ответ не восстанавливался через eval/literal_eval или ручные правки.

Отдельная ошибка ассистента в instrumentation: сначала сохранялось уже разобранное
значение, названное транспортом raw_response. Полный текст восстановлен read-only
по точным request/options cache keys шлюза, длины сверены с исходной телеметрией;
повторных HTTP/LLM вызовов для этого не было. Сохранены все семь текстов и хеши.
Нельзя описывать случившееся как «Ultra прислала только один пример»: это результат
небезопасного извлечения вложенного объекта после ошибки полного документа.

Дальше требуется строгий контракт для ролевых ответов: проверять целый JSON и
ожидаемую схему, сохранять исходный текст до parsing; не превращать повреждённый
документ в успешный вложенный объект. Проверить native json_schema Giga отдельным
ограниченным экспериментом, не засчитывая исправленный формат задним числом.
Потом повторить ролевую цепочку и сравнить Ultra с текущим маршрутом на задачах
с меньшим объёмом готовых подсказок. Старый formatter не повторять.
