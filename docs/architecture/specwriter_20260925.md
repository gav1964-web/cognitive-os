# SpecWriter: продолжение пользовательской задачи

**Обновление26 сентября:** после приведённых ниже неудачных попыток владелец
выбрал GPT-6 Luna у DSLAB. Получена квалифицированная ограниченная спецификация
обработки геометрии; [результат и границы](luna_specwriter_20260926.md).
Ниже сохранена история до этого успеха, включая прежние остановки разрешений.

Дата этапа: 25 сентября 2026. Цель владельца — улучшить преобразование DWG для
отображения стрелок и размеров. Ассистент меняет только COS. Предметные решения,
тестовые данные и ожидаемые результаты должны создавать роли COS. В VR записей нет.

## Текущее состояние

**Спецификация пока не квалифицирована.** Анализ и дизайн повторно использованы
после сверки цели, проекта и исходников. Новые тесты выполнялись только в копиях
внутри COS. Нативная проверка не пропустила ошибочные фикстуры, обращения к ещё
не существующим методам и неработающие прежние регрессии. Programmer не запускался.

Сводки: `artifacts/specwriter_20260925/current-audit.json` и продолжение
`approved-continuation-audit.json` в том же каталоге. Проверенные83 текстовых
исходника VR совпадают с исходным снимком. Это проверка включённых файлов, не
аттестация всего диска или двоичного корпуса.

Последний завершённый опыт: `menu-contracts/run/report.json` под тем же корнем.
Четыре новых случая упали, но этого недостаточно: один неверно описывал сохранение
поведения, другой использовал строку `length` как индекс списка; старые проверки
зависели от отсутствующего в копии двоичного корпуса. Результат остался `blocked`.

Следующий подготовленный опыт `focused-contracts` использует GLM-5.2, максимум
три вызова, выход32768, timeout960s и переносит общий ledger. Автоматическая
проверка разрешений отклонила его запуск из-за передачи исходников внешнему
провайдеру через локальный шлюз. Согласие владельца запрошено отдельно; отказ
не обходился. 26 сентября владелец явно разрешил передачу и продолжение;
подготовленный запуск возобновлён с тем же накопленным бюджетом. Результат
сохранён: HTTP502 `provider_response_unusable`, `response_status=empty` через
498.854с. Usage9454 input +32768 output =42222; текст спецификации не получен.
Повтор того же запроса не выполнялся. Текущий API шлюза не принимает параметр
управления рассуждением; менять шлюз в этом этапе не стали.

Подготовлено переключение на ранее применявшийся `deepseek/deepseek-v3.2`
с теми же контекстом, лимитами и переносом ledger. Автоматическая проверка
отклонила запуск: согласие на GLM-5.2 не распространяется на DeepSeek. Запрошено
отдельное согласие; `focused-deepseek` пока не запускался и ничего не расходовал.

## Что изменено в COS

- Продолжение с готовыми ролями и ранее выбранными диапазонами исходников;
  исправление спецификации по native-ошибкам без повторной генерации анализа.
- Раздельный результат SpecWriter до Programmer и установки; замороженные тесты
  повторно проверяются и передаются дальше без новой генерации спецификации.
- Дополнительный формат JSON-контрактов вызова существующих функций. Модель
  задаёт семантику случаев; COS генерирует только общую pytest-обвязку. Меню API
  строится по исходникам, имён VR/DWG и предметных примеров в механизме нет.
- Для каждого JSON-случая требуется ожидаемый baseline: новое требование падает,
  сохранение поведения проходит. Ошибочный селектор не считается новым дефектом.
- Сохраняется расход всех продолжений. Неизвестный usage останавливает вызовы;
  сверка использует только полные сохранённые счётчики или подтверждённый точный
  cache hit ранее учтённого ответа. Старые журналы не переписываются.

Контракты и ограничения: [feature_development](feature_development.md).
JSON-формат пока не покрывает объектный этап извлечения геометрии, полный импорт
DWG и визуальную приёмку. Его успех нельзя будет назвать выполнением всей задачи.

## Ошибки этого этапа

Первоначальная проверка принимала только Python assert и отклоняла корректные
unittest-проверки. Затем запрет mock оказался чрезмерным: входной объект допустимо
моделировать, подменять production-поведение нельзя. Обе ошибки COS исправлены.

Часть запросов давала модели неполный локальный контекст интерфейса, из-за чего
возникали повторные чтения и неверные фикстуры. Перенос диапазонов и полные тела
функций меню теперь явные. Несколько моделей повторяли отвергнутую структуру
вместо исправления; добавлен отказ идентичного запроса без прогресса. Смена моделей
и формата не дала права объявить спецификацию верной без native-доказательств.

Предыдущий этап с217655 reported tokens и историческими неизвестными резервами
сохранён отдельно в [первом отчёте](feature_goal_20260925.md); не обнулён и не
включён повторно в новый разрешённый пакет. Порог1M — ограничение, не цель расхода.

Финальный этап `artifacts/development/stage-783d61f03d/report.json`:154 focused
tests COS прошли, финализация completed, ограничение400 строк соблюдено.
Навигация проверена (`navigation-handoff.json`). Полный canonical-запуск
остановлен: он включал весь тестовый корпус сверх регрессионного scope этапа;
его пустой `canonical-handoff.json` не является успешной проверкой. Отдельный
`canonical-structure-handoff.json` проверяет архитектуру без полного тестового
корпуса. Focused-тесты проверяют механизм на синтетических проектах, а не качество
работы модели на VR.
Новые числовые оценки ролей не присваивались.

## Продолжение

После разрешения передачи исходников DeepSeek запустить `focused-deepseek`,
перенося `focused-contracts/budget.json`; повторно анализировать проект не нужно.
Если получен `spec_qualified`, проверить смысл всех случаев и явно назвать
непокрытую часть дизайна. До этого не запускать Programmer и не объявлять задачу
SpecWriter завершённой. При отказе разрешения допустимы только локальные проверки.
