# Утечка импортов исполнителя: расследование 29 сентября 2026

Исходный полный прогон имел 542 failed и 46 errors. Три отдельных повтора
проходили. Причина первого отказа теперь воспроизведена: sync/async executor
переставлял `sys.path` и очищал `plugins.*`, но не восстанавливал состояние хоста.
После выполнения pipeline во временной копии последующий вызов KB импортировал
плагин из этой копии. `knowledge_provider_import_origin_mismatch` был корректным
отказом проверки происхождения кода, а не поводом ослаблять эту проверку.

## Доказательства причинности

- Полный fail-fast: 246 passed, затем первый отказ в `test_claim_alignment`.
- Та же коллекция с выполнением только этого теста: 1 passed, 5129 deselected.
- Короткая последовательность async executor → claim alignment: 19 passed,
  затем тот же отказ. Трасса показывает путь `plugins` из временного workspace.
- После исправления: 55/55 профильных тестов, включая оба исполнителя, повторы,
  восстановление после исключения, два параллельных workspace, worker pool,
  происхождение модулей и сохранение полных диагностических логов.
- Проверенный снимок: `artifacts/development/stage-feae8a9599/report.json`.
  Лимит 400 строк и навигационная проверка выполнены.

Исходный механизм переключения импортов не менялся в пакете переносимости ролей:
последний git-коммит executor до этого ремонта — `658c6460`. Это устанавливает
происхождение конкретного дефекта, но не задним числом подтверждает прошлый CI.

## Исправление и границы

`runtime/plugin_import_scope.py` хранит отдельный кэш модулей на один pipeline.
Прямой вызов временно подключает этот кэш, а затем восстанавливает исходные
модули и пути хоста. Кэш сохраняется между узлами и повторами; новый pipeline
получает новый кэш. `asyncio.to_thread` передаёт контекст сессии рабочим потокам.
Вызов и ленивые импорты защищены общей reentrant-блокировкой. Process-bound
worker не меняет импорты родителя и сохраняет параллельность через процессы.

Первая версия ремонта сбрасывала состояние при каждом узле. До завершения
общей проверки обнаружено, что это нарушает `mock://transient_once`; добавлена
сессия pipeline и проверка повтора в обоих исполнителях. Прерванный прогон
`v-3fe4e1fd` сохранён как незавершённый и не учитывается как успешная проверка.

Несколько старых тестов сами оставляли изменённый `sys.path` или удалённые модули.
Теперь тест ошибочной сигнатуры использует тот же scoped import, лишние очистки
и вставки пути в других тестах удалены. Проверки происхождения и hash не ослаблены.
Это работа с импортами доверенного кода, не изоляция произвольных побочных эффектов.

Каноническая проверка сохраняет полные stdout/stderr на диск во время выполнения,
JUnit для каждого набора и ссылки в отчёте. Раньше сохранялись только последние
1600 символов, из-за чего диагностика потребовала дополнительного воспроизведения.

## Общая проверка

После устранения утечки полный повтор `v-1b1a852a` дал 5057 passed / 73 failed.
Оставшиеся причины разобраны отдельно:

- `frame_specification` требовал `project`, даже когда необязательного
  `product_context` нет. Прежние входы снова допустимы; передача контекста без
  проекта отклоняется явно. Проверки чужого/подменённого контекста сохранены.
- Пять исторических DeepSeek-тестов наследовали локальную настройку Luna.
  Теперь модель фиксируется в тестовой конфигурации; production model guard сохранён.
- Smoke fixture не содержала всех каталогов, перечисленных в plugin manifests.
  После их добавления выявлено превышение Windows path length во вложенных тестах.
  `check_plugins` использует короткий временный каталог и сохраняет его путь.
- Native probe иногда оставлял пустой JUnit. Теперь сохраняются exit code и
  timeout receipt; пустой, обрезанный или отсутствующий отчёт не может подтвердить
  успешность патча. Точная OS-причина исторических пустых отчётов не доказана:
  прежняя диагностика не сохраняла необходимые сведения.
- Общий тестовый native timeout увеличен до 60 секунд и согласован с политикой
  ролевой цепочки. Production default не изменён. Несогласованность этих двух
  тестовых настроек вызвала последние пять `invalid_or_stale_trace`; проверка
  целостности trace была корректной и не ослаблялась.

Сохраняется отрицательный результат внешнего curriculum: map и test004 — 1.0,
test5 — 0.963, `needs_improvement`. Не хватает evidence для исторической ссылки
`app/providers/adapters.py:generate_result`. Старый тест ошибочно требовал полного
успеха на изменяемом внешнем корпусе. Теперь он проверяет правдивость отчёта;
добавлен отрицательный контроль. Frozen-тесты сохраняют требование 1.0.
Дефект качества выделен в отдельную задачу, reference и алгоритм не подгонялись.
