Задача VR по отрицательным многовитковым дугам **завершена**:9 native-тестов,
оба прежних контрпримера Challenger обнаруживаются,8 внешних проверок проходят;
поставка проверена в копии. Итог продолжений: **3/5 исходных задач +1/1

Оригиналы проектов неизменны. Исторический результат замороженной COS0/5 не
переписывается; общие баллы ролей не повышаются.

## Механизм

`runtime/feature_accepted_metadata.py` хранит вместе baseline_expectations и
case_plan квалифицированных тестов. Повторное использование требует совпадения
цели, архитектуры, полного source inventory и точных байтов теста. Новые прогнозы
для уже принятых неизменных тестов не нужны: runtime восстанавливает исходные
строки, сохраняя исходный ответ и изменения в receipt. Неизвестные/дублированные
строки не удаляются; новый/изменённый тест не наследует старые метаданные.
Свежий семантический аудит и native-квалификация всей приёмки остаются обязательны:
новые fixtures/imports могут влиять даже на неизменённый тест.

При resume новый оплаченный черновик после более раннего одобрения аудитора
восстанавливается как **непринятый**, с проверкой goal/design/source binding.
Предыдущее одобрение не переносится. Восстановление отклонённого аудита понимает
детерминированное возвращение квалифицированных метаданных и проверяет их по
источнику, а не доверяет таблице в новом запросе.

`runtime/feature_candidate_reuse.py` добавляет Python API `resume_candidate_from`
к quality/development. Старый COS-кандидат должен иметь native receipt и одобрение
Reviewer, совпадающие цель/проект/исходники/архитектуру. Текущая квалифицированная
приёмка сохраняет все прежние тесты и выбранные regressions. Патч исполняется
заново; production hashes должны совпасть, разрешены только дополнительные
квалифицированные тестовые файлы. Reviewer вызывается заново. Известная кампания
Challenger переносится, несовместимые кампании не объединяются молча.

Если новые тесты обнаружили ошибку в старом патче, исправление получает Programmer.
Если не совпали хеши патча, цикл останавливается. Тест подмены выявил прежний
дефект общего routing: native-green мог направить mismatch к Reviewer. Этот
переход закрыт; нарушение целостности не исправляется одобрением другой роли.
Переиспользование не расширяет write-scope и не разрешает переписывать приёмку.

Offline replay обнаружил зависимость двух таблиц: восстановление только прогноза
baseline оставляло конфликт с заново написанной категорией case_plan. После
совместного восстановления9 прогнозов совпали с native baseline:6passed,

проверенный патч. Он прошёл расширенные9 тестов. Понадобился только один новый
