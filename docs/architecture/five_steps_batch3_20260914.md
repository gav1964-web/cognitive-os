## Что произошло в реальном цикле

Первая гипотеза получила четыре полных assertions и точный контрпример второго
пакета для table-cell whitespace. Модель заполнила все пункты плана, но кандидат
использовал `parent_tags[-1]`. В native вызове `parent_tags` — множество, поэтому
возник `TypeError: 'set' object is not subscriptable`.

COS корректно сохранил отказ, но не смог передать его в повторный диагноз:
traceback занимал 14 265 символов, а прежний feedback принимал максимум 6000.
Исправление инфраструктуры сохраняет полный native output и передаёт только
явно обозначенный точный суффикс длиной 2000 символов, с границами и хешем полного
текста. Парсер по-прежнему проверяет исходный полный вывод, а не его суффикс.
Короткие контрпримеры сохраняют прежний формат без обрезания.

После исправления цикл продолжен отдельным вызовом core API с оставшимся
бюджетом двух логических запросов; старый receipt не переписывался. Это ручное
восстановление инфраструктурного сбоя, не полностью автономный uninterrupted retry.
Заявленный общий лимит четырёх запросов соблюдён. Исходники COS заморожены отдельно
для каждой попытки; обе source checks успешны. Ответы модели вручную не исправлялись.

В продолжении модель применила перебор множества, но поместила исправление
заголовка после неизменённого раннего `return ""`. Поэтому assertion для заголовка
снова получил `foobar` вместо `foo bar`. Наличие R1 и четырёх объяснений не
предотвратило повтор уже известной ошибки порядка ветвей.

## Контракты

`runtime/repair_assertion_contract.py` строит `repair_assertion_contract.v1` из
полных test excerpts и проверяет их hashes. Поддержаны прямые Python assertions
в теле одной test function; assertions в условных/вложенных блоках, непрозрачные
helper checks и неполные excerpts отклоняются. Максимум 64 assertions и ограниченный
объём. Это все assertions переданных excerpts, не весь проект и не доказанная
полнота тестирования. Параметризованные nodeids сохраняются.

`model_require_assertion_plan=true` явно включает требование `assertion_plan`:
каждый ID ровно один раз, в заданном порядке, с объяснением требуемого поведения.
Default false. Наличие объяснения проверяется структурно; его истинность — только
через native evidence. Полный `assertion_contract` и `assertion_plan` входят в
`repair_grounding`; Spec/Plan должны совпадать с дизайном выбранного кандидата.
Совместное удаление этих полей из обоих артефактов не проходит admission.

Prompt projection исключает повторяющиеся file hashes/locations из каталога,
сохраняя каждое assertion, ID, nodeids и digest полного контракта. Полный контракт
остаётся в дизайне. Это явная проекция, а не молчаливое обрезание obligations.
Размер гипотезы по-прежнему ограничен 24k символов для nominated trial, 12k для
обычного; превышение останавливает запрос.

`run_project_development(..., repair_counterexample_comparison=...)` допустим
только в явно разрешённом модельном trial. Перед использованием сверяются
source/packet, точные candidate bytes/provenance, повторные baseline signatures,
patched inventory и полный native output. Saved evidence не выдаёт новое
разрешение на исполнение и не делает consumed development независимым holdout.

## Следующий подход

Не считать дополнительные поля схемы улучшением способности ремонтировать код.
Приоритет — source-bound различающие наблюдения о типах аргументов и реально
пройденных ветвях для каждого требуемого контекста, проверка выполнимости дизайна
и сохранение накопленных противоречий. Один последний контрпример не должен
вытеснять более раннюю ошибку whitespace или раннего возврата.
Перед расширением prompt/schemas оценить пользу ограниченным сопоставимым
экспериментом на сохранённых случаях, с заранее объявленным бюджетом и учётом
ручных вмешательств. Независимые баллы требуют отдельного свежего holdout.
Текущий пакет завершает только свои пять шагов, новых model calls после лимита нет.
