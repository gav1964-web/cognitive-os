# Явные требования в проверяемом native-ремонте

Дата: 13 сентября 2026. Продолжение проверки причинных предложений.
Область — один подтверждённый failure target и существующий учебный оператор;
общая способность создавать новый диагноз не заявляется.

## Изменения первых трёх ролей

- Analyzer сохраняет контракт задачи и проверяет его привязку к production-символу.
  Карта возможных вызовов содержит строки и хеши просмотренных Python-файлов.
  Это совпадения имён; aliases, shadowing, dynamic dispatch и внешние потребители
  не разрешены. `complete_call_graph` всегда false. Лимиты: 128 файлов, 4 MB общего
  текста, 1 MB на файл, 128 ссылок; пропуски перечисляются.
- Architect получает испытанное предложение и проверку требований на его точной
  копии. Сигнатура, аннотации и декораторы выбранной функции должны сохраниться.
  Свежесть просмотренных исходников проверяется перед выполнением тестов.
- SpecWriter сохраняет все пользовательские требования как MUST, добавляет
  traceability к native-тестам и передаёт проверенный repair delta.
- Reviewer проверяет неизменность требований, evidence и итогового patch.
  Чужой зелёный patch не может унаследовать результаты выбранного вмешательства.

## Контракт исполнения

Новый `task_contract` доступен в `run_project_development` вместе с
`authorize_training_replay=True` и `validate_causal_proposals=True`.
CLI `tools/project_development.py` принимает `--task-contract <workspace-relative.json>`.
Сам контракт не даёт authority: нужны существующий разрешённый учебный маршрут,
поддержанное сравнение предложений и последующие полная регрессия/Reviewer.
Обычный `run_role_pipeline` с task_contract сохраняет planning-only режим.

Каждое требование указывает production target и существующие pytest nodeid:

```json
{
  "id": "PRESERVE",
  "statement": "Сохранить значение существующего пути",
  "targets": ["src/envforge/store.py:EnvConfigStore._get_literal"],
  "acceptance_examples": [{
    "kind": "native_test",
    "nodeid": "tests/test_path_descent_contract.py::test_existing_path_keeps_value",
    "baseline_expectation": "passes",
    "expectation": "passes"
  }]
}
```

Для исправляемого наблюдения `baseline_expectation` равен `fails`.
Проверяются реальные nodeid и результаты setup/call/teardown в исходной и
исправленной копиях. Сбой setup, пропуск или снятие теста с выполнения не дают
подтверждённого результата. Не более 32 связей требований и 16 уникальных nodeid.
Произвольные constraints, свободные input/output-примеры без native-теста,
несколько production targets и запросы не типа defect остаются неподдержанными.
Семантическую достаточность выбранных тестов утверждает вызывающая сторона;
автоматическое понимание текста требования этим не доказано.

## Сквозные доказательства

`artifacts/verification/requested_contract_linux_v2_20260913.json`: известный EnvForge,
два явно переданных требования, шесть наблюдений. До изменения: 5 failures и
1 pass; после: 6 passes. Затем полная native suite **85 passed**, финальный
Reviewer **approve**, результат `experiment_validated`. Карта: 16 Python-файлов,
4 возможные ссылки, без пропусков в этом ограниченном сканировании.
Исходный проект, рабочий COS и замороженная копия COS сохранены.

Requirements подготовлены ассистентом по уже известным наблюдениям; fixture и
оператор также ранее написаны ассистентом. Нового диагноза, patch или правила для
EnvForge на этом этапе не добавлено. Вызовов LLM — 0. Это интеграционный результат
на потреблённом development-примере, не независимый holdout и не повышение баллов.

Первые unit-прогоны выявили ошибку адаптера: абсолютный путь созданной копии
передавался функции, принимающей относительный путь. Исправлено преобразование
с проверкой принадлежности workspace; запрет выхода за границу сохранён.

Первый успешный прогон `requested_contract_linux_20260913.json` сохранён отдельно.
Последующий аудит нашёл устаревшие идентификаторы во вспомогательной таблице
требований, хотя основная таблица и исполнение были корректны. Все представления
acceptance теперь синхронизированы; Reviewer отвергает устаревшие ссылки.
Повтор v2 снова прошёл всю цепочку и 85 native-тестов без изменения исходников.

Проверки: `artifacts/verification/requested_contract_tests_20260913.xml`,
`artifacts/verification/requested_callers_20260913.xml` (57 существующих проверок),
`artifacts/verification/development_stage_requested_20260913.json` (финальный
снимок основной регрессии: 700 passed / 4 skipped),
`artifacts/verification/development_stage_requested_v2_20260913.json`
(финальная коррекция ссылок, профильные регрессии, память решений и 400 строк),
`artifacts/verification/canonical_requested_20260913.json`.
Негативные случаи включают лишнее невыполненное требование, неверное ожидание
baseline, отсутствие теста, подмену требования/patch, снятие теста с выполнения,
дрейф параметра функции и устаревшую карту исходников.
Пакеты проверены отдельно: `artifacts/verification/subprojects/ad0794da/report.json`,
по 27 успешных тестов Inspect и Replay.

## Продолжение

Исполнимая передача поддержанного native-контракта реализована. Следующий пробел —
новые проверяемые гипотезы из наблюдений, более точное разрешение callers и
реальный случай без заранее подготовленного диагноза/оператора. Существующий
LLM hypothesis API пока не подключён к сравнению новых предложений; provider usage
и независимая оценка остаются открытыми. Задача `upstream-causal-design` сохраняется.
