## Минимальное расширение общего протокола

`runtime/plugin_loader.py:load_capability` выделяет существующую проверку одного
плагина; загрузка всех плагинов сохраняет проверку fallback references.
`config/knowledge_providers.json` перечисляет ID провайдеров, предоставляемые
каталоги и владельцев profile IDs. Предметных алгоритмов в нём нет.
`runtime/competency_knowledge.py` вызывает существующий plugin entrypoint,
проверяет вход/выход, active lifecycle, зарегистрированный hash, происхождение
импортированного кода и неизменность плагина во время вызова. Запись другого
владельца и неоднозначное владение отклоняются.

Общий boundary interpreter объединяет legacy-записи с вкладом провайдеров,
проверяет декларативные условия и передаёт выбранный профиль владельцу для
обогащения. Он не содержит pickle ID, imports или специальных веток.
Параметр `active_patterns` перемещён в API владельца. Явный `path` загрузчика
проверяет конкретный файл; вызов без `path` собирает каталог для указанного `root`.
Config doctor и тестовый corpus helper переведены на составной каталог.

Результаты KB не кешируются. Изменение её содержимого делает прежний registry hash
неверным; после проверенного обновления регистрации следующий вызов видит новые
данные. Изменение уже загруженного кода требует нового процесса. Политики
promotion и применения патча сохраняются; зарегистрировать hash не значит
повысить качество или разрешить запись в исходный проект.
