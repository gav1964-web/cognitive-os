# GeminiVM: диагностический вопрос между ошибкой и повтором

22 сентября 2026. По поручению владельца восстановление service_error проверяет
ответ на другой короткий запрос. Реализация и принятие решения остаются внутри
GeminiVM; шлюз5 и COS не запускают дополнительных циклов.

По умолчанию service_error_probe=true. При распознанной внутренней ошибке
провайдер задаёт «What is 2 + 2? Reply with only the number.» в новом чате той же
модели. Только normal с ответом4 (допускаются внешние Markdown/точка/пробелы)
разрешает повтор исходного prompt без изменений, также в новом чате. Вопрос
о текущем времени заменён арифметическим: он имеет проверяемый ответ без поиска.
Это узкая проверка простого запроса, не доказательство здоровья сервиса или
установленной причины исходного сбоя.

Общий max_attempts3 включает диагностический вопрос: задача → диагностика →
задача. Для диагностики резервируются два оставшихся слота. При меньшем остатке
цикл останавливается. Пустая страница расходует тот же бюджет. Диагностический
запрос не имеет своих повторов; его timeout=min(response_timeout,120 секунд),
настраиваемый diagnostic_timeout10–180. Сохраняется общая desktop lock,
проверка UI, URL, выбранной модели и clipboard readback.

Неудачная диагностика сохраняется в отдельном attempt-N.json с kind=diagnostic,
текстом, состоянием, моделью и ошибкой; потребителю возвращается исходный
service_error. Диагностический ответ и его источники не подменяют результат
задачи. HTTP/JSON добавляет diagnostic_count; retry_count считает только повторы
основной задачи. Для успешной цепочки это1/1, при неудачной диагностике1/0.
Счётчик диагностики означает начатую попытку: UI может остановить её до submit.

service_error_retries0 отключает восстановление service_error. Явное
service_error_probe=false сохраняет прежние прямые повторы; они также ограничены
max_attempts3. max_attempts1 выключает повторы. UNKNOWN/login, обычный timeout,
refusal/stub и цитата ошибки в полезном ответе не запускают диагностику.
Per-task timeout и таймаут внешнего клиента не изменены: предел числа отправок
не гарантирует завершения внутри внешнего таймаута. Usage остаётся unknown.
