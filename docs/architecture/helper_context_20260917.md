# Пакет: контекст вспомогательных функций

Дата: 17 сентября 2026. Продолжение [проверки реального проекта](claim_transfer_20260917.md).
Артефакты: `artifacts/helper_context_20260917/`.

## Пять работ

1. **Индекс локальных вспомогательных функций.** Плагин project_description0.8.0
   выделяет переданные Python-секции и прямые вызовы функций из того же файла.
   Параметры, локальные присваивания/imports и вложенные области не считаются
   связью с модульным helper; дубликаты исключаются, циклы завершаются.
   Это синтаксические кандидаты, не доказанная привязка во время исполнения.
2. **Отбор контекста review.** Цитируемые исходники и дополнительные чтения получают
   больше места, чем вспомогательные тесты/документация. Предел на один источник
   увеличен1800→4000 символов, общий evidence+packets остаётся32000. Отбор сохраняет
   целые доступные секции, включая их исходные отметки сокращения; он не читает
   другие файлы и не дорисовывает отсутствующий код.
3. **Чтение реализации вместе с callers.** Запрос top-level Python-функции включает
   до шести helpers из того же файла, в том числе транзитивно, в пределах10000
   символов. В отчёте есть диапазоны, число пропусков и неполнота caller.
   Хеш, границы пути и редактирование литералов credentials проверяются как прежде.
   Импорты из других файлов и attribute calls не разрешаются автоматически.
4. **Offline-воспроизведение.** В сохранённом исходном контексте Inspect новая
   выборка сохраняет доступные условия определения фреймворков и тело определения
   назначения скрипта. После тех же трёх запросов к исходникам расширенное чтение
   возвращает полные реализации, которые остаются в финальном review. До изменения
   обе нужные детали отсутствовали. Лимиты соблюдены:31877 символов на первом
   review и31579 после чтения. Старые receipts не изменены; новых model calls
   на этом шаге нет. Регрессии используют также вымышленные имена и проекты.
5. **Живое измерение на двух проектах.** Inspect — известный случай; Replay — другой
   настоящий многомодульный компонент. Обе серии используют обычный describe_project,
   без специальных подсказок с названиями helpers или ожидаемыми ответами.
   Критерии заранее записаны отдельно. Это внутренние проекты, не независимый holdout.

## Уточнение прошлого заключения

В прошлом отчёте формулировка о наличии тела `_frameworks` в черновике была
слишком сильной. Сохранённый исходный excerpt содержит сокращённое определение
и выбранные условия, а не полное тело. У `_purpose` тело было полным. Новое
изменение сохраняет эту разницу: доступный фрагмент остаётся сокращённым, а
дополнительное чтение получает полное определение из файла с проверенным хешем.
Имена здесь — свидетельства конкретного прогона, не условия в production-коде.

## Бюджет и свидетельства

Постоянное разрешение владельца: новые пакеты строго ниже1млн input+output
токенов без повторного согласования. Резерв899304 на максимум6 запросов: по три
на проект,130000 UTF-8 входных байтов и3500 выходных токенов на запрос плюс запас.
Это рабочий резерв, не гарантированный предел биллинга. При неизвестном расходе
последующие вызовы блокируются. Счётчик не включает сессию ассистента разработки.
Timeout240с, без retry/fallback. Исторические серии не возобновляются.

Offline: `baseline_context.json`, `restored_context.json`, `expanded_lookup.json`,
`expanded_review.json`. Живые: `protocol.json`, `authorization.json`,
`token_budget.json`, `inspect_*`, `replay_*`. Итоги — `summary.json`, проверки
завершения — `verification.json`. Прохождение инженерных тестов не повышает баллы ролей.

## Итог живого измерения

На Inspect обе прежде потерянные детали сохранены: примеры Flask/FastAPI и
назначение установки зависимостей. Исходный запрос и черновик побайтово/по JSON
совпадают с предыдущим прогоном; шлюз сообщил cache_hit=true и0 tokens для
черновика. Два запроса review новые:28913 tokens против27616 ранее. Поэтому
снижение полного расхода не является экономией от нового отбора контекста.
Это один парный прогон с двумя изменёнными механизмами и без контроля случайности
модели; общего роста качества из него не следует.

На Replay черновик отклонён до review: `data_flow` — объект вместо требуемого
списка. Один запрос,19762 tokens. Исходный ответ сохранён; повторов и молчаливой
нормализации не было. Даже после исправления формы ему требуется смысловая
проверка: не назван двойной baseline-прогон, успешные тесты описаны как достаточные
для квалификации, а неизменность источника — как гарантия вместо проверки flags.
Перенос улучшения на второй проект не установлен.

Итого4 запроса к шлюзу, один из кеша;48675 reported tokens (45471 входных,
3204 выходных),141,066с суммарной задержки. Два зарезервированных слота не
использованы. Все usage известны; обе серии закрыты, исходники двух пакетов
не изменены. Четыре инженерные работы завершены; пятая работа — измерение —
выполнена с положительным результатом на Inspect и отказом на Replay.

Файлы: [описание Inspect](../../artifacts/helper_context_20260917/inspect_description.md),
`inspect_review.json`, `replay_review.json`, `summary.json`. Старые десять claim
receipts повторно проверены без изменения статусов. Для защиты новых чтений
добавлена проверка длинного credential-литерала: редактирование выполняется до
обрезки, которая могла бы удалить закрывающую кавычку. Живые входы этого случая
не содержали; поведение подтверждается регрессионным тестом.
