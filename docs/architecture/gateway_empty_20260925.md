# Пустой upstream-ответ и учёт ошибки — 25 сентября 2026

Исправлен сбой, остановивший [парное сравнение](cos_prompt_pair_20260925.md).
Изменения установлены в шлюз5, процесс на порту8000 перезапущен штатным скрытым
bootstrap COS, `/health` доступен. Артефакты: `artifacts/gateway_empty_20260925/`.

**Автор инфраструктурного исправления — ассистент, не COS.** Платных модельных
вызовов в этом этапе не было. Ролевые оценки и production prompt не менялись.
Это отдельный ремонт провайдерного контура, не принятие старого модельного патча.

## Контракт

Раньше OpenAIAdapter обращался к `response.choices[0]` до проверки структуры и
извлечения usage: `None` приводил к TypeError, пустой список — к IndexError.
Теперь общий helper извлекает доступный usage и безопасные идентификаторы модели,
проверяет список/сообщение/текст, затем выдаёт результат либо ProviderError:
`code=provider_response_unusable`, `http_status=502`, `retriable=false`.
Пустой ответ не превращается в успешный completion.

В `/v1/chat/completions` управляемая ошибка содержит `usage` (либо null),
ограниченные `provider_diagnostics` и request ID. Сохраняются только разрешённые
поля; сырой body, prompt, credentials и произвольные детали не публикуются.
`resolved_model` — безопасное имя из upstream response.model, если оно сообщено;
`requested_model` остаётся отдельным. Это декларация upstream, не аттестация весов.
Для совместимости основное result.model_name остаётся запрошенным именем.

При успешном ответе текст, reasoning, параметры запроса и usage сохраняются.
Обработчик пустого ответа не делает повторных запросов. Существующие SDK-повторы
для транспортных ошибок и явно настроенные failover profiles не переписывались;
число внутренних SDK-попыток по-прежнему не доказано отдельной телеметрией.

COS читает разрешённые usage-поля также из HTTP-ошибок и добавляет их к telemetry
и failure evidence. Поэтому ошибочный completion с сообщённым положительным
total_tokens учитывается бюджетом как известный расход, оставаясь ошибкой без
оценки качества. Отсутствующие, отрицательные, строковые, bool и дробные counts
не превращаются в нули. Нулевой total не снимает прежнее ограничение BudgetedChat
на доказательность расхода. Значения ограничены неотрицательным signed64 integer.

## Проверки и установка

- 48 offline-тестов на копии шлюза: malformed responses, usage, API envelope,
  успешные ответы, существующие диагностика/маршрутизация и error mapping.
- 30 focused-тестов COS: доставка failure evidence и учёт ошибки через настоящий
  BudgetedChat с подменённым HTTP, без обращения к внешней LLM.
- После установки повторены19 новых проверок непосредственно на исходниках5;
  установленные SHA256 совпали с проверенной копией.
- Пять gateway-файлов установлены с проверкой исходных хешей и резервной копией.
  Все изменённые Python-файлы шлюза меньше400 строк. Finalization COS выполняется
  отдельно и содержит расширенную регрессионную проверку.

Первая попытка тестов выявила отсутствие routing fixture в изолированной копии;
добавлена только разрешённая часть `routing_profiles.geminivm_resilient` для
существующей offline-проверки. Настройки/секреты провайдеров не копировались.
Первая проверка разрешения перезапуска истекла по времени, команда не исполнялась;
разрешённый повтор успешно запустил шлюз. Это не функциональный отказ исправления.

## Незавершённое сравнение

Расход старого HTTP500 восстановить нельзя: новый обработчик не меняет прошлую
телеметрию. Прежний неизвестный слот сохранён; нулевой расход не подставлялся.
Парный эксперимент пока не возобновлён. Для новых вызовов с сохранённым резервом
на неизвестный старый расход запрошено отдельное изменение правила остановки
из DEVELOPMENT_TASKS.md. До ответа — только проверки без внешней LLM.

Задача пустого ответа закрывается по установленным исходникам, тестам и restart
receipt. Задача полной атрибуции SDK-попыток остаётся открытой. Никаких выводов
о преимуществе краткого prompt или достижении ролями9+ этот этап не добавляет.
