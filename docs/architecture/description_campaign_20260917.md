# Пять шагов: понимание проекта, review и передача ролям

Дата:17 сентября2026. Автор инженерных изменений — внешний ассистент.
Проверка описаний выполнена COS через DeepSeek v3.2. Независимых ролевых баллов нет.

## Что сделано

1. Зафиксированы прежние ответы map, VR и5 с хешами и уточнениями владельца:
   `tests/fixtures/project_description/accepted_baselines.json`. Это evaluation-only
   история; она не подмешивается в рабочие инструкции. Замечание ассистента о
   переключении проекции VR оспорено владельцем и не является установленной ошибкой.
2. Компетенция0.2.0 строит ограниченный граф локальных Python-импортов и ссылок
   HTML/JS; entrypoints и их зависимости получают приоритет. Вспомогательные файлы
   явно помечены. Каталог содержит пути, хеши и имена символов. Это синтаксические
   связи и эвристики, не доказательство достижимости всех ветвей исполнения.
3. Reviewer может один раз запросить до3 фрагментов по функции/классу или диапазону
   строк (до301 строки и10000 знаков каждый). Только известный каталог, хеши,
   разрешённые исходники; traversal/private paths и изменения источника отклоняются.
   Каждое утверждение черновика имеет действие и обоснование review. Для опубликованных
   фактов обязательны ссылки на источники. Удалённые без доказательств утверждения
   сохраняются как вопросы полноты и передаются следующей роли.
4. Проведена одна фиксированная серия VR,5 и Cognitive Inspect с общей неизменной
   политикой и timeout240с. Исходные неудачи сохранены. После серии исправлена только
   трактовка пустых ссылок у метаданных удалённого утверждения; повторных сетевых
   запросов и подбора подсказок под проекты не было.
5. Добавлен `product_context.v1`: явно рассмотренные утверждения, уточнения владельца,
   неизвестные вопросы, ограничения и пробелы review проходят через Analyzer,
   Architect и SpecWriter с проверкой корня, digest и актуальности источников.
   Контекст остаётся advisory и не даёт права исполнять патчи.

## Небольшая реальная доработка

Для Cognitive Inspect зафиксированы review описания и ограниченный task contract.
Реальные функции COS сформировали Analyzer → ArchitectureDecisionRecord → TechnicalSpec;
во всех трёх сохранился одинаковый product_context. Task source binding — source_bound,
выбран bounded_in_place_change. SpecWriter оставил needs_design и запрет исполнения:
артефакты COS сами по себе не доказывают готовую реализацию.

Внешний ассистент проверил конкретный дизайн: тонкий stdlib CLI-адаптер поверх
публичного scan_project_tree, JSON на stdout, ошибки на stderr/exit2, существующие
ограничения пути и бюджета сохранены. Затем ассистент реализовал
`python -m cognitive_inspect PATH --max-files N --max-depth N`.
До изменения `python -m cognitive_inspect --help` завершался с кодом1 из-за отсутствия
__main__; после изменения CLI проверен в subprocess и в установленном wheel.
Это assisted development, не самостоятельный ремонт COS.

VR и5 не изменялись; хеши прочитанных исходников совпали. Inspect намеренно изменён
после описания и формирования плана (новый CLI, тесты, README); старое описание
не переобъявляется описанием новой версии без свежей проверки источников.

## Что ещё не достигнуто

Reviewer всё ещё может ослабить правильное описание, а дочитывание — израсходовать
бюджет на второстепенные функции. Следующая работа: уменьшить первичный контекст,
дать проверке адресные пути вызовов и исключить повторный запрос уже выданных данных;
проверять изменения прежде всего на сохранённых транскриптах. Новую модельную серию
ограничивать отдельным бюджетом. Нельзя считать этот этап подтверждением9.7,
универсального улучшения или автономной разработки.
