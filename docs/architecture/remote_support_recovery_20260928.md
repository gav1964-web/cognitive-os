# Раздельные права и аварийный учёт COS — 28.09.2026

Реализован файловый исполнитель под отдельной Windows-учётной записью и
контроллерный учёт расхода, сохраняющий резерв при потере процесса.
Платных LLM-вызовов в этом пакете нет; предыдущие53225/900000 не изменены.

## Проверено

Контроллер работал от Alex, worker — от существующей ограниченной учётной записи
Codex. Новые каталоги стенда получили отдельные ACL; пользователей, системных
служб и прав существующих проектов не меняли. Использован случайный тестовый ключ.
Полный offline-цикл: исходный отказ → патч → reproduce → regression → resume.
На каждом из пяти исполнений worker не смог прочитать или открыть на запись
ключ, policy и state контроллера; также не смог изменить request.json.
Суммарно35 проверок отказа доступа в финальном комбинированном пилоте.
Источник сохранился; активировалась исправленная копия. Поведенческий дефект
в этом ACL-пилоте внесён намеренно; новых оценок ролей это не даёт.

Реальные подпроцессы принудительно завершались после записи ready/started/done.
Дополнительно проверен настоящий FeatureChat с офлайн-транспортом: остановка
после durable started сохраняет неизвестный резерв; остановка после settlement
сохраняет сообщённый расход без итогового worker JSON. Смерть самого контроллера
проверена отдельным подпроцессом после сохранения резерва, до вызова worker.

80 профильных тестов: аварии, повреждение/удаление ledger, подмена расхода,
неизменность истории, повторная доставка, зависший exchange, права контракта,
запрет повторного исполнения захваченного задания и сохранение ролевых результатов.

## Контракты

`accounting: "role_ledger.v1"` — opt-in policy контроллера. Для живого
`remote_role_worker` теперь обязательно; старые deployment policy нужно обновить
перед новым запуском. Исторические receipts не переписываются.
Контроллер до spawn резервирует весь выделенный остаток. После подтверждённого
завершения сверяет закреплённый job, pointer и ledger, неизменность прежних calls.
Отчёт worker не может заменить этот учёт. Утраченный/повреждённый журнал оставляет
полный резерв, начатый вызов — свой неизвестный резерв, done — reported usage.

При смерти контроллера либо таймауте файлового обмена worker может ещё работать:
полный резерв остаётся, статус `needs_operator`. `reconcile --worker-stopped`
доступен только как локальная операция контроллера после проверки завершения
worker. Она уточняет расход, но не подтверждает результат задачи и не возобновляет
побочные эффекты. Неизвестный provider usage нельзя объявить нулевым этим флагом.

`execution` в policy содержит `kind: "windows_file_worker.v1"`, абсолютный
`root` обмена, `controller_sid`, `worker_sid`. SID различаются, identity контроллера
проверяется при dispatch. Exchange должен быть отдельно от source, home и outbox.
Контроллер готовит запрос с read-only ACL; worker может менять только source/output
копии. CLI worker проверяет свою identity, claims файл до запуска, оставляет claim
при аварии; захваченное задание не повторяется автоматически. Timeout не доказывает
остановку отдельного worker и не освобождает резерв.

```powershell
# Выполнять под заранее выделенной учётной записью worker:
python tools/remote_support_worker.py --exchange C:/cos-exchange --worker-sid WORKER_SID --seconds 60
# Выполнять локально у контроллера только после проверки остановки worker:
python tools/remote_support.py --key-file controller.key reconcile --home controller-state --outbox to-assistant --worker-stopped
```

## Границы результата

Доказан запрет доступа к controller-файлам в новом локальном стенде, а не sandbox
всего Windows-хоста. Worker имеет остальные права своей учётной записи. Для
постоянного развёртывания нужны выделенная учётная запись, защищённые родительские
каталоги (без права worker подменить путь deployment) и самостоятельный lifecycle
службы. Стенд в workspace и временная учётная запись Codex не объявляются такой
production-конфигурацией. Ключевые файлы старых проектов и реальные credentials
не использовались. Внешний файлообменник не настроен.

Сверка ledger предполагает доверенный аутентифицированный код worker; она не
является независимой выпиской провайдера и не защищает от worker, намеренно
фальсифицирующего весь inference ledger. Реальный платный ролевой цикл под
разными Windows-аккаунтами остаётся отдельной проверкой; прошлый Luna-пилот
проходил под одной учётной записью.
