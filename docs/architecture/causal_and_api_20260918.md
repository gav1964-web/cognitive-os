Продолжение: [gateway_resume_20260918](gateway_resume_20260918.md). Отсутствие шлюза было ошибкой ассистента: согласованный штатный автозапуск был пропущен. Шлюз поднят, живые проверки завершены; ниже сохранён отчёт исходного этапа.

Пакет из пяти работ продолжает оба направления. Инженерное расширение выполнено;

## 1–2. Причина и место исправления Toml-sort

Восемь проверок на неизменённой копии исходников охватывают comment-only документ
и документ с телом при четырёх сочетаниях header/footer. Для comment-only вывод
содержит 0/1/1/2 экземпляра комментария: ни один режим, только footer, только header,
оба режима соответственно. Гипотеза о лишнем переводе строки недостаточна:
дублируется содержимое, которое независимо добавляют два пути.

Место исследования изменено с `write_header_comment` на `toml_doc_sorted`:
эта функция координирует оба пути и видит `items` и `footer_comment`. Новая
номинация проходит существующую проверку источников, трассы и допустимой области;
наблюдения исходного теста собраны заново дважды. Исходники корпуса не изменены.
Номинация и её причинное обоснование сделаны ассистентом, поэтому это не
доказательство автономной зрелости Analyzer/Architect/SpecWriter.

Требования: устранить дублирование, сохранить header-only и footer-only,
обычные документы и форматирование; принять патч только после исходного
падающего теста, полной регрессии и финального Reviewer. Контроли не являются
универсальной спецификацией всех сочетаний настроек.

## 3. Ограниченная попытка ремонта

Свежий baseline: 33 passed / 1 failed / 2 xfailed. Один запрос к модели через
обычный direct proposal route с новой номинацией и новыми наблюдениями завершился
`URLError`; кандидата нет, Reviewer не достигнут. Отдельная TCP-проверка получила
ConnectionRefusedError / Windows 10061 на `127.0.0.1:8000`.

Общий пакет заранее ограничен девятью вызовами, без retry/fallback, с резервом
ниже миллиона токенов. Телеметрия не получена; расход неизвестен, его нельзя
записывать как ноль. Остальные восемь вызовов не запускались. Серия закрыта;
старые результаты и бюджет не переписываются. Необязательные общие LLM-анализы
при ремонте были явно переведены на детерминированный fallback, как в прошлом
эксперименте; это отдельное вмешательство ассистента.

## 4. Плагин project_description 0.14.0

Добавлен opt-in selector `normal_return_for_inputs`: `inputs` вместо `field`,
остальные поля связывают источник, функцию и фрагмент утверждения до ответа LLM.
Пустой объект inputs означает вызов с пропущенными аргументами. Проверяется
связывание параметров, литеральные Boolean/None defaults, keyword-only параметры
входной функции и возможность нормального возврата для этого конкретного вызова.

Значение по умолчанию None не означает, что тело функции принимает None. Отсутствие
обязательного аргумента и моделируемый raise дают контрпример; неизвестный backend,
неподдержанный код и вычисляемые defaults оставляют результат unknown. Контрпример
не превращается автоматически в смысловое опровержение: положительное мнение
модели о связанном фрагменте только понижается до uncertain.

Нормальный возврат, включая None или объект со статусом ошибки, не доказывает
успешный полезный результат. Это особенно существенно для Replay: его API может
вернуть `environment_blocked`, а не бросить исключение. Для полного описания нужно
проследить environment profile до валидатора и различать нормальный возврат и
успешную квалификацию. Новый ограниченный механизм не решает весь этот анализ.

Алгоритм, KB, схемы и ограничения принадлежат плагину. Runtime только связывает
данные и проверяет сохранённые доказательства. Основной маршрут генерации описаний
не изменён; шесть прежних property receipts проходят повторную проверку.

## 5. Свежие проверки и полное описание

Шесть новых авторских контролей: omitted input rejected, explicit input accepted,
valid default, helper rejection, opaque backend и нормальный возврат None.
Анализ даёт заранее ожидаемые исходы 6/6. Заведомо уверенный синтетический ответ
проверяет понижение verdict; это не новый результат LLM и не независимый holdout.
Профильные тесты сравнивают конечную модель с настоящим Python только на тестовых
fixtures; исходники анализируемого проекта анализатор не исполняет.

baseline и расширенная инструкция плагина. До запуска зафиксированы требования
сохранить полезные детали, условия environment profile, повтор baseline,

отправлены** из-за неизвестного расхода предыдущего запроса. Улучшение полного
текста, стоимости и задержки не измерено.
