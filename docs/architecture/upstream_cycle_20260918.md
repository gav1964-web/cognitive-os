# Проверка первых трёх ролей — 18 сентября 2026

Пакет из пяти шагов завершён. Два ограниченных ремонта прошли полную ролевую
цепочку и финальный Reviewer с точными модельными исправлениями. Независимый
уровень 9.7+ не установлен. Оба проекта — авторские development fixtures:
overlay повторяет ранее потреблённый инвариант, batches — новый контраст,
а не независимый внешний holdout. Общая модель и критерии допуска не изменены.

Артефакты: `artifacts/upstream_cycle_20260918/`. Исходные проекты и модельные
ответы сохранены; правок модельного кода ассистентом нет. Первоначальные ошибки
подготовки и остановки не считаются модельными неудачами.

## 1. Измерение реальной цепочки

Заморожены два исходника, native tests, требования и бюджет до inference:
`cases.json`, `protocol.json`, `budget.json`. Использован существующий
`run_project_development` с hypothesis route, assertions и requested acceptance.
BudgetedChat оборачивает транспорт; ответы модели не подменяются. Это один общий
LLM-диагноз/дизайн и один генератор кандидата, а не три независимых LLM-роли.
Architect и SpecWriter оформляют и проверяют артефакты общей цепочки.

| Случай | Первоначальная остановка | Итог COS |
|---|---|---|
| overlay: дубли ключей исходного списка | Диагностический probe поддерживал только методы классов; модель не вызывалась | 2 вызова, 4 native tests passed, Reviewer approve |
| batches: равенство суммарного веса вместимости | Повторяющиеся значения переменных превысили 12000-char бюджет гипотезы; 0 вызовов | После сжатия 2 вызова, 5 native tests passed, Reviewer approve |

Receipts: `overlay/result.json`, `batches/result.json` (остановка),
`batches/compact/result.json` (успех). В обоих успешных запусках все 11 checks
эксперимента истинны. Исходные проекты не изменены; исправлены только sandbox-копии.

## 2. Analyzer: наблюдаемое выполнение и точность объяснения

Native probe теперь наблюдает обычную синхронную функцию модуля, сохраняя
проверку code identity, исходников и повторяемости native failure. Декораторы,
async/generator и неоднозначные определения отклоняются. Область номинации
методов классов не расширена. Имена захватываемых переменных задаются явно;
opaque/nested values сохраняют существующие ограничения сериализации.

В модельном контексте повторные locals передаются изменениями от предыдущего
события. Все события, sequence, строки и return сохранены, исходные снимки
остаются в receipt. Для batches контекст уменьшился с 8048 до 3401 bytes.
Регрессия восстанавливает полные снимки без потерь. Бюджет запроса не повышен.

Точность диагноза не равна успешному ремонту: overlay верно указывает на дубли,
но ошибочно описывает первоначальную обработку base как обновление значений.
В batches причина `>=` вместо `>` объяснена правильно, однако precondition
ошибочно исключает нулевой вес. Эти текстовые ошибки не исправлены автоматически.

## 3. Architect: дизайн, исполненная ветка и место остановки

Оба изменения действительно затрагивают проявившийся дефект; targeted replay,
requested preservation tests и full native regression подтверждают результат
на этих случаях. Это не уникальное доказательство причинного объяснения.

Исправлена передача диагностической остановки: requested-change binding больше
не заменяет предыдущую конкретную причину общим `unique_supported_candidate_required`.
Детали отказа гипотезы/транспорта сохраняются. Кандидат, опровергнутый native tests,
направляется Architect для согласования дизайна и реализации; это адрес следующей
работы, не автоматическое обвинение роли в семантической ошибке.

## 4. SpecWriter: достаточность проверок

Исправлены две ошибки отчётности: проверенное requested execution authority
больше не считается непроверенным; аудит перепроверяет existing acceptance proof,
а не верит одному флагу. SpecWriter указывает фактическое исполнение caller tests
на baseline/candidate, не утверждая независимую генерацию или полноту тестов.

`acceptance_audit_v2.json`: намеренно неправильные изменения проверены сначала
исходными тестами, затем расширенным набором. Исходные тесты пропустили сортировку
ключей вместо порядка первого появления. Ассистент добавил противоположный порядок,
проверку неизменности base при дублях и нулевой вес после заполненной пачки.
Оба точных модельных исправления прошли по 6 tests; все 7 неправильных кандидатов
отклонены расширенными наборами. Это post-hoc усиление ассистентом, не самостоятельная
работа SpecWriter и не независимый holdout.

Первый `acceptance_audit.json` сохранён как история: удаление capacity guard
оказалось no-op из-за CRLF в harness. Во втором запуске исправлен только генератор
этого мутанта; AST-проверка запрещает выдавать неизменённый код за отрицательный
контроль. Остальные результаты воспроизведены.

## 5. Перенос и описания проектов

Две новые противоположные маленькие библиотеки проверены полным writer/review:
`descriptions/required/` и `descriptions/working_default/`. Исходник, README и
ожидаемое поведение заморожены до запросов. README намеренно противоречит коду.
Оба текстовых результата получены, но критерии качества не выполнены:

- При default None модель не объяснила, что пропуск профиля возвращает blocked,
  и перенесла из README ложную гарантию неизменности. Renderer лишь помечает её
  как не подтверждённую реализацией; это не устранение ошибки.
- При рабочем default True модель не объяснила успешный вызов без аргумента
  и описала переданный Boolean как подтверждение сохранности данных.

Имеющийся API плагина правильно различает успешные и ошибочные default-вызовы.
Добавлены противоположные проверки success и diagnostic flag против CPython.
Whole-function анализ с default-параметрами остаётся unknown; конкретный вызов
проверяется через `analyze_inputs`. Детерминированные свойства пока не связываются
автоматически с каждым утверждением полного текста. Новых правил для имён проектов
и изменений plugin KB в этом пакете нет.

## Расход, вмешательства и проверки

8 запросов, **26384 reported tokens**, unknown 0; консервативный резерв 419840.
Одна фиксированная запрошенная модель `deepseek/deepseek-chat`, без failover и
платных повторов. Ремонт: 7606 и 8873 tokens, полная цепочка около 73 и 53 секунд.
Описания: 4897 и 5008 tokens. Это расходы COS, не токены работы ассистента и не
счёт провайдера. Прежние unknown других кампаний не списаны.

Телеметрия теперь сохраняет allowlisted finish_reason, наличие и длину конечного
content до проверки JSON. Пустой ответ имеет отдельную ошибку; скрытое рассуждение
не сохраняется, повтор автоматически не добавляется. На этих успешных запросах
причина прежних пустых ответов GLM/R1 не установлена; новую серию не запускали.

Вмешательства: авторские задачи/тесты и capture fields, расширение probe,
сжатие контекста после локального отказа, исправление provenance/feedback,
post-hoc тесты и оценка текстов. Модельные кандидаты не редактировались.

Итоговая проверка и receipt этапа: `verification.json` и `finish.json` в каталоге
пакета. В них сохранены результаты regression scope, архитектуры и 400-line gate.
Смена defaults, применение исправлений к внешнему корпусу и повышение ролевых
баллов не выполнялись.

Следующий результат: перенести цепочку на существующий небольшой внешний проект;
потребовать от SpecWriter обнаруживать недостаточность acceptance до генерации
исправления; связать проверяемые предусловия/диагностику с итоговыми утверждениями
описания и снова выполнить противоположные контроли. Не повторять сравнительный
перебор моделей и не считать ещё один оформленный артефакт ростом зрелости.
