# Первые три роли: явный резерв и происхождение ответа

23 сентября 2026. Analyzer, Architect и SpecWriter используют профиль
`geminivm_pro` с одним резервом `deepseek_role_backup` через тот же шлюз5.
Основная модель остаётся `geminivm/pro`; резерв — `deepseek/deepseek-chat`,
timeout180с, JSON response_format, max_output_tokens32768.
Профиль описания проекта и существующая связка общего L4.5 DeepSeek→GigaChat Pro
в этом этапе не изменены. Это операционный выбор, не новое ранжирование моделей.

Используется прежний общий `llm_failover`, без отдельного цикла в GeminiVM или
повторной реализации маршрутизации в шлюзе. На один `call_json_chat` каждый
маршрут вызывается не более одного раза; для этих профилей максимум два вызова.
Текст задачи передаётся резерву без изменений. Ранее существовавшие локальные
повторы исправления формата/контекста у потребителей этим лимитом не заменяются.
Общий deadline GeminiVM1500с остаётся ограничением одного запроса провайдера,
а не всего ролевого pipeline вместе с резервом.

Переход при квоте, сетевой недоступности, HTTP408/429/5xx сохраняет прежнюю
политику cooldown. Новое явное `fallback_on_codes` допускает только:
`refusal`/`suspected_stub` при HTTP200/422 и `busy` при409. Профиль первых трёх
ролей включает эти три кода; остальные профили по умолчанию их не используют.
Обычный422, content_filter, auth/config failures и невалидный JSON не запускают
новый semantic fallback. Текст ответа классифицирует провайдер; COS проверяет
его объявленный код. Refusal не ставит модель в глобальный cooldown, поскольку
такой исход относится к конкретной задаче. Неуспех обоих маршрутов сохраняется
как отказ с прежним pending-task поведением, а не успешный результат.

`attempt_failed` сохраняет reason_code, HTTP status, индекс и модель попытки.
Телеметрия успешного ответа содержит фактическую сообщённую модель и fallback_used.
Артефакты Analyzer deliberation, Architect advisory и SpecWriter arbitration
теперь разделяют requested_model и model; добавлены resolved_provider,
model_reported, fallback_used и ограниченный список route_failures с причинами.
Значение source сохраняет прежнее назначение
контекста вызова. `runtime/inference_origin.py` принадлежит Roles и передаёт
телеметрию существующему потребителю; исходное содержание ответа не изменяет.
Если провайдер не сообщает модель, model_reported=false: имя маршрута не выдаётся
за независимое подтверждение модели провайдером.

Проверки разработки:71 targeted tests и59 дополнительных проверок потребителей.
Они включают opt-in, неизменность prompt, две неуспешные попытки без цикла,
сохранение причины и credential isolation, отсутствие ложного переключения
по произвольному422 и правильную модель в артефактах всех трёх ролей.
Evidence: `artifacts/role_fallback_20260923/tests.xml`, `consumers.xml`.

Ограниченный рабочий эксперимент использует исходный публичный formatter prompt
из предыдущего этапа. Начальный отказ Gemini воспроизводится из сохранённого
receipt; в Gemini ничего повторно не отправляется. Продуктовый failover выбирает
резерв, которому разрешён ровно один новый HTTP-вызов. Кандидат проверяется
на прежнем native-наборе в копии, без ручного изменения кода. Это сочетание
сохранённого отказа и живого резерва, не новый полностью живой двухмодельный цикл
и не независимое измерение уровней ролей.
Evidence: `artifacts/role_fallback_20260923/live/protocol.json`, `events.json`,
`calls.json`, `summary.json`; предыдущий baseline127 passed /7 failed /1 xfailed
повторно используется только после проверки полного source inventory.

## Результат рабочего эксперимента

Сохранённый отказ Gemini корректно активировал DeepSeek Chat; новый запрос к
Gemini не выполнялся. Один живой HTTP-вызов к резерву завершился за21,438с;
вместе с native-проверкой28,578с. Шлюз сообщил model=deepseek/deepseek-chat,
cache_hit=false,7200 входных и326 выходных токенов, всего7526.
Это сообщённый usage, не подтверждение биллинга и не расход прежней Gemini-попытки.

Точный кандидат не принят:101 failed /33 passed /1 xfailed вместо исходных
7 failed /127 passed /1 xfailed. Код обращается к ast.Tuple без импорта ast
и связывает решение с первым AST-выражением всего файла. Это не ремонт нужной
границы обработки фрагмента. Ассистент код не исправлял; исходный корпус и
тестовые критерии не менялись, состав тестов сохранён, патч остался в копии.

Работа резерва и сохранение происхождения подтверждены; качество результата
в этой задаче неудовлетворительно. Уровни ролей не повышаются. Новые модельные
вызовы после этого результата не выполнялись. Следующая работа должна проверить
качество причинного диагноза и допустимую область ремонта, прежде чем расширять
набор провайдеров или повторять ту же генерацию.
Evidence: `live/summary.json`, `live/candidate.patch`, `live/candidate-probe.json`,
`live/events.json`, `live/http-response.json`, `live/calls.json`.
