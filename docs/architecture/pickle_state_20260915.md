# Разделение функционала и отдельная правка pickle

15 сентября 2026. Пользователь уточнил цель текущего этапа: разделение
функционала по владельцам с сохранением поведения. Рост точности, независимый
benchmark или внешняя development-задача не являются условиями следующего
проверенного переноса. Предыдущее предложение остановить миграцию до прироста
качества было избыточным; план и память решений исправлены.

## Локальное исправление

Pickle-компетенция 0.1.1 проверяет полноту явно переданного рецепта конструктора:
в `required_constructor_inputs` должны входить все объявленные параметры,
включая параметры со значениями по умолчанию и keyword-only. Повторяющиеся имена,
пропущенные именованные параметры и используемые `*args`/`**kwargs` отклоняются.
Неиспользуемые вариативные аргументы сохраняют прежний поддержанный маршрут;
прямые locals/vars/eval/exec обращения блокируют их пропуск. Это ограниченная
AST-проверка, не доказательство отсутствия произвольной рефлексии. Генератор возвращает
`None`, зарегистрированный контракт — `not_applicable` без патча.

Это исправляет выдачу известного кандидата, терявшего `retryable=True` при
воспроизведении только обязательных аргументов. Рецепт автоматически не
расширяется. Если `retryable` явно включён в рецепт, прежняя стратегия
восстанавливает сохранённое значение; keyword-only вариант по-прежнему требует
`allow_keyword_only_state_reducer=True`.

Изменены только локальный генератор, его тесты, версия/регистрация плагина и
документация. Общие интерпретатор и provider dispatch не изменены. Содержимое
активной KB, её provenance и допуск не пересматривались. Source apply,
authorization, native regression и Reviewer сохраняют прежние полномочия.

## Доказательства

Первоначальные coverage-тесты перед исправлением: 6 failed / 2 passed / 1 deselected,
`artifacts/verification/pickle_state_red_20260915.xml`. Зарегистрированный вызов
исключён из red-прогона, пока новая версия с тестами ещё не зарегистрирована.
После уточнения вариативных аргументов профильные проверки и authorized runner:
`artifacts/verification/pickle_state_focused_v2_20260915.xml` — 36 passed.

Сохранённые исходники и тесты предыдущего замера повторены без изменения:
`artifacts/verification/pickle_state_v2_20260915/result.json`.

| Проверка | Результат |
|---|---|
| Обычные сохранённые аргументы | Предложение, 3/3 native checks passed |
| Неполный рецепт с `retryable` | `not_applicable`; исходный дефект остаётся, 1/3 checks passed |
| Существующий reconstruction hook | Отказ от правки, прежние 3/3 passed |
| Преобразованные аргументы | Прежний отказ, исходные 1/3 passed |
| Тот же `retryable`, явно полный рецепт | Предложение, 3/3 passed |

В последней строке рецепт дополнен ассистентом явно; это не самостоятельный
вывод Analyzer и не автоматический ремонт всего ролевого pipeline. Проверки
используют настоящий pickle round-trip, `__dict__`, `args`, тип и сообщение.
Прежние результаты замера сохранены отдельно.

Первый широкий прогон `artifacts/verification/pickle_state_regression_20260915.xml`
дал 208 passed / 3 failed: запрет всех вариативных аргументов оказался чрезмерным
для прежнего конструктора с игнорируемыми `*args`/`**kwargs`. Запрет уточнён по
использованию и захвату локального namespace, старые тесты сохранены.
Полный повтор регрессии на финальном снимке этапа:
`artifacts/verification/development_stage_pickle_state_20260915.json`.
Модельных вызовов 0, независимые ролевые оценки не пересчитываются.

Полнота параметров закрывает конкретную потерю omitted/default input, но не
доказывает сохранение любых post-construction атрибутов, slots или пользовательских
протоколов. Такие требования по-прежнему проверяются native-тестами конкретного
кандидата. Безопасная поддержка неполного рецепта потребует отдельного дизайна.

## Продолжение разделения

Следующая структурная работа — карта оставшихся pickle-потребителей и выделение
исследовательской оркестрации/контрактов, затем следующий владелец знаний.
Критерии: нет второго редактируемого источника знания, нет специальных веток
в общем слое, контракты работают, сохранены результаты и полномочия.
Качество алгоритмов и производительность измеряются отдельными задачами;
их прирост не является дополнительным условием структурной миграции.
