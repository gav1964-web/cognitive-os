# Первые реальные исполнители task15: 12 сентября 2026

Подключены три маршрута и проведены три инженерные попытки. Один direct-agent
доставил CLI, прошедший собственные 6 тестов и 6 внешних проверок. Независимых
троек по протоколу v2 по-прежнему **0**: нет подтверждённых стоимости/usage и
слепой оценки, а успешный direct использовал две модели.

## Что исполняется

`python tools/run_evaluation_routes.py` поддерживает пока только
`task15_uppercase_cli`. Он проверяет готовность входов, сохраняет manifest,
хеш checker, inventory исходников и отдельные каталоги маршрутов. По окончании
проверяет неизменность maintained sources. Флаг `--route` выбирает один маршрут;
`--model-route failover|primary|backup` выбирает штатный failover или одну модель
без изменения продуктового профиля. Значение по умолчанию — `failover`.

| Маршрут | Реализация | Граница интерпретации |
|---|---|---|
| direct_agent | `evaluation/executors/workspace_agent.py`: JSON-действия list/read/write/verify/finish | Малый агент с файлами и фиксированной проверкой; не универсальный агент с shell |
| short_chain | Настоящий greenfield Architect/SpecWriter без вызова L4.5, затем тот же агент с компактным ProductTechnicalSpec | Измеряет добавление текущего планировщика; не произвольную выдуманную цепочку ролей |
| full_chain | Настоящий `run_role_pipeline` с native executor и advisory LLM | Текущий pipeline ориентирован на изменение существующего проекта; готовность greenfield не предполагается |

Общие transport/verification — `runtime/evaluation_route_execution.py`, адаптеры —
`runtime/evaluation_route_adapters.py`. Direct не получает ролевые артефакты COS;
его агент не импортирует COS. Общий хост использует клиент шлюза и один checker.
Для native Architect транспорт временно подменяется на измеряемую обёртку в
отдельном процессе, с сохранением настоящих prompts и контрактов pipeline.

Каждый маршрут получает исходный prompt, constraints и success criteria. Входы
копируются в соседний `inputs/`, виртуально доступны агенту только для чтения;
output project начинается пустым. Это важно: анализатор проекта не должен
принимать синтетические fixtures другой задачи за код требуемого продукта.
Лимиты: 900 секунд, не более 20 вызовов/учтённых попыток, 3000 output tokens за
вызов, общий бюджет 120000. Перед вызовом резервируется UTF-8 byte estimate плюс
output allowance; после ответа используется положительный reported total либо
консервативный резерв. Это ограничитель, а не измеренная стоимость токенизации.

Проверка запускает pytest по всему output project и требует хотя бы один
пройденный тест, затем отдельно проверяет шесть условий CLI. Внешние ошибки
возвращаются агенту для исправления в том же бюджете; это не sealed holdout.
Подпроцесс имеет ограниченный environment, но права текущего пользователя:
OS/container sandbox не реализован.

## Результаты и вмешательства

Все ссылки ниже находятся под `artifacts/evaluation_v2/` в локальном workspace.
Исходники во время каждого прогона оставались неизменными. Ручных исправлений
внутри попыток не было; между попытками ассистент менял harness, как описано ниже.

| Попытка | direct | short | full |
|---|---|---|---|
| `routes_20260912T071324Z` | Не принят: неверный pytest target и CRLF; остановка бюджета | Остановка бюджета | Занялся fixture `table_reader.py`, CLI не доставлен |
| `routes_20260912T073026Z` | **Принят: pytest 6, внешние 6/6**, 41.625 с; DeepSeek + GigaChat-Pro | LocalInferenceError, 56.125 с | `rework_role_artifacts`, CLI отсутствует, 18.016 с |
| `routes_20260912T073654Z` | LocalInferenceError, 61.391 с | LocalInferenceError, 62.954 с | HTTP 503 в Architect advisory, `rework_role_artifacts`, 16.547 с |

Первая попытка обнаружила ошибки нашего harness: inputs были частью анализируемого
проекта, pytest искал только `tests/`, большой план short расходовал резерв,
исключение бюджета теряло события агента, диагностика checker скрывала различие
байтов LF/CRLF. Это исправлено до второй попытки. Шесть критериев checker сохранены;
добавлены ожидаемые/полученные байты для положительных случаев. Поэтому первая
попытка не является чистым измерением качества маршрутов.

Третья попытка использовала фиксированный GigaChat-Pro во всех запросах. У direct
и full не было записанного успешного ответа; model label не восстановлен догадкой.
Остановка прямого агента сохранила только класс ошибки, поэтому точную причину
его сбоя установить по receipt нельзя. У full HTTP 503 виден в native pipeline.
Нулевые usage шлюза у short трактуются как неизвестные. После третьей попытки
добавлена безопасная запись `attempt_failed` для ошибки единственного провайдера,
включая HTTP status и факт наличия ответа. Это покрыто регрессией; ещё один live
запуск после этой диагностической правки не выполнялся. Старые журналы сохранены.

`draft.json` каждого маршрута содержит artifacts с хешами, попытки моделей,
проверки и ошибки допуска v2. Drafts находятся вне canonical receipts и не
повышаются автоматически. Стоимость остаётся `null`, неизвестные токены — `null`.
`trial_recorded` означает сохранение попытки, а не успешность всех маршрутов.

## Выводы, которые выдерживают эти данные

- Реальный агент способен решить task15 в этом ограниченном окружении.
  Успех смешанной генерации не доказывает качество одной конкретной модели.
- Допущение о готовности native full-chain для пустого проекта не подтвердилось.
  Нужен явный greenfield handoff до реализации и тот же внешний acceptance.
- Failover работал на реальной ошибке DeepSeek в первой серии. Это повышает
  доступность в отдельных случаях, но не гарантирует успешность резервной модели.
- Шлюз сообщает model ID, но нулевые usage и отсутствие биллинга не позволяют
  достоверно сравнить стоимость. Скорость успешного и заблокированного маршрута
  нельзя интерпретировать как преимущество последнего.
- Данные не подтверждают превосходство COS, оценки 9.7+ или перенос на свежие дефекты.

Следующие действия сохраняются в DEVELOPMENT_TASKS.json: native greenfield
доставка, диагностика шлюза/учёт usage, затем одинаковая модель и независимая
слепая оценка. Остальная кампания 26 задач и свежий buffer defect не закрыты.
