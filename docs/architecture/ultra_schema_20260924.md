# Строгие ролевые ответы и native schema Ultra: 24 сентября 2026

Остановленная цепочка завершилась: тот же запрос SpecWriter с native schema
вернул допустимый документ, следующий точный патч Ultra прошёл **74/74** прежних
native-проверок против **66/74** на исходнике. Улучшение формата подтверждено
одним повтором известного случая; общего роста оценок ролей из этого не следует.

## Контракт COS

`runtime/structured_inference.py` отвечает за транспортный контракт документа,
без знаний предметной области. `LocalInferenceConfig` поддерживает:

- `strict_json`: весь JSON-объект либо один полный Markdown JSON fence. Проза,
  повреждённый документ, вложенный спасённый фрагмент, повторные ключи и
  нестандартные NaN/Infinity constants отклоняются.
- `response_schema`: локальная проверка JSON Schema, автоматически требующая
  строгого разбора. Внешние `$ref` не загружаются; ошибочная схема блокирует HTTP.
- `response_format`: прежний bool либо явно заданный объект для API. Native
  формат задаётся для конкретного маршрута и не переносится на чужой fallback.
- `raw_response_sink` и `raw_response_limit_bytes`: сохранение финального текста
  до parsing, с SHA256, размером и явной отметкой усечения. По умолчанию предел
  262144 байта; неполное сохранение не допускает успешного приёма результата.

Схемы задают потребители: Analyzer signals/deliberation, Architect advisory,
SpecWriter arbitration. Их прежние семантические проверки остаются нужны.
Role profiles и явные configs в role pipeline включают strict mode. Legacy
generic consumers сохраняют прежнее извлечение JSON из текста; это отдельный
режим, который не применяется к новым ролевым контрактам.

BudgetedChat сохраняет `response_evidence` в receipt перед разбором, в том числе
при ошибке формата; usage остаётся известным и учитывается. Поле `raw_response`
в старом API receipt по совместимости остаётся разобранным объектом: его нельзя
путать с новым исходным текстом. Нативная schema включена в резерв размера входа
и fingerprint запроса. В role pipeline evidence присоединяется к соответствующей
записи вызова; прямой клиент может использовать callback, а ошибка строгого
разбора несёт `response_evidence`. Общие метрики не получают текст, credentials
и скрытые reasoning-поля не копируются. Ошибка сохранения evidence блокирует
выдачу успешного результата. Failover сохраняет локальную схему, strict mode и
evidence sink, но использует wire format резервного маршрута.

## Живой повтор

Вход SpecWriter байтово соответствует сохранённым сообщениям предыдущей серии.
Добавлен `response_format={type:json_schema,schema:...,strict:true}` и локальная
валидация. Форма параметра сверена с [официальной документацией GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output).
Резерв **258304**, два слота, max output32768, temperature0, top_p0.9 шлюза,
timeout300 с, без повторов и fallback. Оба запроса прошли COS → шлюз5 →
`GigaChat-3-Ultra:32.9.23.6`; cache_hit=false, retry_count=0 по телеметрии.

| Вызов | Результат | Reported tokens | Время |
|---|---|---:|---:|
| SpecWriter | Полный JSON, локальная schema пройдена, 13 примеров | 7464 | 18,672 с |
| Код по принятой спецификации | Точный патч, native74/74 | 10766 | 44,312 с |

Итого **18230 reported tokens**, unknown0, сумма вызовов62,984 с. Это не счёт
биллинга и не время всего инженерного этапа. Исходные ответы сохранены до
parsing, восстановления из кэша больше не требовалось. Старый ошибочный ответ
сохранён и теперь отклоняется целиком офлайн.

Смысловая оговорка SpecWriter: NaN/Infinity представлены строками. Эти два
примера не являются исполняемыми тестами float без отдельного кодирования типов.
Остальные 11 конкретных примеров согласованы с контрактом. Допуск к коду был
условным на прохождение заранее замороженных тестов с настоящими float NaN/inf;
подсказок модели и исправлений её файла ассистентом не было.

## Интеграция и проверки

Точный модельный файл проверен в копии прежнего COS, с одинаковыми тестами и
коллекцией. Затем ассистент перенёс только guard точного положительного int в
текущий `local_inference.py`, сохранив новые strict/schema/evidence изменения.
Это интеграция проверенной логики, а не утверждение, что весь текущий файл
написан Ultra. Дополнительно исправлено сохранение нулевого/False лимита в
failover: он должен попасть на отказ, а не замениться лимитом маршрута через `or`.
None и65536 сохранены. Новые тесты проверяют invalid значения с fallback и без.

Финальный snapshot: 171 профильный тест контракта/интеграции и consumers прошёл.
Проверка сборки/установки обоих подпроектов выполнена из локального wheelhouse:
33+27 тестов. Первое обращение к PyPI завершилось timeout, receipt сохранён;
сетевой сбой не трактуется как дефект патча. Начальный запуск с PyPI вместо
доступного wheelhouse был лишней задержкой со стороны ассистента.
Полный canonical test run остановлен ассистентом после более20 минут в общем
наборе, во время длительного pipeline/Foundry теста; результата всего набора нет.
Завершён структурный canonical checkpoint (`--skip-tests`) и отдельный проверенный
snapshot171 тест. Эти области не выдаются за полный зелёный CI.
Все receipts, включая остановку, отражены в `verification.json`.

Выбор основных моделей сохранён. Следующее — перенос на менее подготовленные
реальные задачи и парное сравнение Ultra с текущим маршрутом; native schema
решает формат, но не причинную точность и полноту спецификации. Старый formatter
не повторять. Кандидат HTTP mapping из прежней серии остаётся неустановленным.

Evidence: `artifacts/ultra_schema_20260924/`: protocol/budget, calls с исходным
текстом, schema review, точный candidate/native probe, интеграционные тесты,
canonical, subprojects, stage-finish и `verification.json`.
