# GeminiVM: исправление ввода и автозапуск из шлюза

21 сентября 2026. Запрос владельца: исправить блокировки ввода GeminiVM и
автоматически запускать провайдер на8002 из проекта `5`, если он не работает.

## Поведение

- Проверка browser readback допускает только позиционную замену SPACE на NBSP,
  сохраняя существующую обработку NFC/переводов строк. Изменения длины, табов,
  иных символов и обратная замена буквального NBSP на SPACE отклоняются.
  Исходный запрос сохраняется. Это проверка представления в браузере, а не
  разрешение менять Python-код или утверждение о равенстве произвольных текстов.
- Перед вставкой записывается собственный неотправленный черновик. Восстановление
  из PROMPT_TYPED допускается только после проверки URL и совпадения поля с этим
  черновиком. Чужой/изменённый текст останавливает работу. Маркер удаляется до Enter,
  поэтому неопределённый результат уже отправленного запроса не пересылается.
- `5` проверяет `/v1/models` при старте и перед запросом GeminiVM. При отсутствии
  локального endpoint запускает соседний проект GeminiVM его `.venv` Python,
  скрыто, без shell; ожидает готовности30с. Учитываются ConnectError и Windows
  ConnectTimeout. Async-блокировка и файловая блокировка защищают запуск от гонок.
  Работающий процесс сохраняется при перезапуске шлюза. Удалённый endpoint локально
  не запускается; отвечающий несовместимый сервис не заменяется вторым процессом.
- Настройки: `GEMINIVM_PROJECT_DIR`, `GEMINIVM_PYTHON`, `GEMINIVM_AUTOSTART=0`.
  Журнал: `5/logs/geminivm.log`. Ожидание ответа GeminiVM1200с, SDK шлюза1800с,
  повторы SDK0. Встроенный повтор service_error в GeminiVM остаётся равным1.
