# map: понятный статус импорта силами COS

27 сентября 2026. Владелец выбрал предложенное улучшение статуса импорта.
COS/Luna сформировала анализ, дизайн, тесты и патч. Ассистент правил только общие
механизмы COS, передавал обратную связь диагностике и проверял свидетельства.
Установка выполнена `runtime.feature_workspace.install`, с резервной копией.

## Пользовательский результат

В корневом приложении `F:/ubuntu/test/map` появился отдельный блок состояния
импорта. Он различает LLM, отключённую или недоступную модель, частичные ошибки
пакетов и неизвестный режим старых данных. Предупреждает о возможном снижении
точности при правилах/резервной обработке. Число успешных обращений к LLM
отделено от числа действительно принятых событий: пустой успешный ответ не
даёт основания писать «LLM помогла». Новые сведения сохраняются в метаданных
набора; обновление страницы и счётчиков событий не стирает сообщение.

Сводка не включает исходные ошибки провайдера, адреса и секреты. Это ограничение
новой сводки; прежний служебный endpoint вывода импорта отдельно не переработан.
Извлечение событий, геопривязка, категории и формат прежних полей не менялись.
Изменения метаданных аддитивные. Старые наборы автоматически не переимпортируются:
если новых сведений нет, интерфейс показывает неизвестный режим.

COS установила `app.py`, `import_indoc.py`, `tests/test_import_transparency.py`.
Уже существовавшие пользовательские изменения сохранены. Хеши всего текстового
каталога совпали с исходным каталогом плюс эти три изменения. Дополнительные
входные файлы карты/справочника/ресурсов неизменны. Подготовленный каталог
`map_install_package` не пересобирался: улучшение относится к корневому приложению.
Работающий сервер на порту5000 во время завершения не обнаружен; сервер не запускали.

## Проверка и границы

| Свидетельство | Результат |
|---|---|
| Замороженная приёмка до патча |11 assert-провалов,1 сохранённое поведение |
| Точная новая версия и повтор после установки |12/12, без ошибок и пропусков |
| Повтор прежней модельной backend-диагностики на копии реальных данных |17/17 |
| Повтор прежнего браузерного сценария на копии реальных данных |12/12 |
| Новый браузерный сценарий на синтетических данных |7 вариантов метаданных,84/84 проверок |
| Заключительный Reviewer |approve,goal_complete=true |

84 проверки включают HTTP, отсутствие секретов, тексты, видимость, сохранение
статуса после перезагрузки и смены группы, отсутствие JS/HTTP/сетевых ошибок;
это не84 независимых пользовательских сценария. В дополнительных проверках
невалидные типы статуса дают unknown без исключения. Скриншот частичного отказа
просмотрен ассистентом: предупреждение видно в отдельном блоке панели.

Браузер работал через настоящий Flask test_client с виртуальным локальным origin,
внешние запросы блокировались. Это не проверка сетевого HTTP-сервера/установщика.
Живой внешний LLM-импорт не выполнялся: его состояния проверены синтетическими
метаданными, CLI-путь — без LLM. Следовательно, надёжность реального провайдера
и сравнительная точность импорта не измерены. В заключительном отзыве Reviewer
сохранил ограничение «production corpus excluded»: это верно для замороженной
pytest-приёмки, но дополнительные17+12 checks использовали копию реальных данных.
Они остаются ограниченной диагностикой, не исчерпывающей приёмкой корпуса.

## Что изменилось в COS

1. Проекты без `test_*.py` могут явно использовать `new_preservation_only`.
   Нужны и настоящий assert-провал новой функции, и проходящее прежнее поведение.
   Ноль прежних тестов не выдаётся за пройденную регрессию. Существующий набор
   обходить этим режимом нельзя.
2. Повторяющиеся пути в ответе Programmer получают один форматный retry;
   область записи и запрет правки замороженных тестов сохранены.
3. При содержательном отказе Reviewer продолжение повторяет точный кандидат
   и передаёт отказ Programmer. Принятая приёмка остаётся замороженной.
4. Reviewer получает точный diff проверенного кандидата и хеши, отличая его
   от оригинальных исходников, которые возвращает обычное чтение.

Эти механизмы не содержат веток/KB по имени map. Контракты и регрессионные
проверки описаны в [brief](feature_development.md).

## Ошибки и стоимость

Первая спецификация не квалифицировалась; COS исправила её по native feedback.
Последующие патчи проходили8/12,11/12 и12/12. Часть повторов вызвана чрезмерно
буквальными проверками русских фраз и регрессиями этих фраз при переписывании
кандидата. Первый зелёный патч Reviewer отклонил по существу: успешный ответ
LLM был принят за доказательство её вклада. Эта ошибка исправлена моделью.
Ещё один review остановился, поскольку модель не сочла представление исходника
и замен достаточным; точный diff и дополнительные наблюдения дали завершённый review.

Первая браузерная диагностика COS превысила200 строк, потеряла часть пути Chromium
и содержала лишнюю проверку с постоянным true. Ассистент отклонил её до исполнения;
COS исправила. Следующее исполнение обнаружило неверную сигнатуру route callback
(аргумент Request перекрывал Flask client); COS исправила точными заменами.
Неудачные предложения/receipts сохранены. Первый post-install запуск ассистента
ошибся относительным путём к pytest.ini; повтор с абсолютными путями дал12/12.

Это выполненная пользовательская задача, но не полностью автономная разработка:
помощь ассистента в инфраструктуре и диагностике была существенной. Новые общие
механизмы устраняют обнаруженные остановки; экономия следующих запусков ещё
не измерена. Числовые оценки первых трёх ролей не повышаются автоматически.

Этап: **29 вызовов,714534 reported tokens,unknown0**. Вся серия map:
**38 вызовов,887498 из разрешённых2млн**. Старые172964 перенесены; серию VR
не возобновляли. Модель во всех новых вызовах `dslab-gpt6-luna`, без fallback,
лимит выхода32768, timeout480с. Шлюз проверялся до учёта каждого запуска.
Стоимость заметна для небольшой функции: повторный контекст и ошибки тестов
остаются направлениями улучшения COS, а не свидетельством зрелости9.7+.
