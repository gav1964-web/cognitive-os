# Пять задач на реальном VR — 25 сентября 2026

**COS написала и после native feedback исправила патч, установленный в VR.**
Неизменная приёмка: **21/27 → 27/27**, установленная версия: **20/20** проверок
клиента и viewer API. Код `_request` взят из ответа модели без ручных исправлений.
Исходник сохранён в `artifacts/vr_five_20260925/vr-backup`.

## Выполненные пять задач

1. Разобрана прежняя остановка. Модель получала тело падающего теста, но проверки
   сохранения поведения — только как nodeids. Инструкция подробно описывала отказ,
   не объясняя достаточность свидетельств для гипотезы. Это обнаруженные свойства
   контекста; причинное объяснение модельного отказа ими не доказано.
2. В COS добавлен общий `requested_acceptance_context`: исходники приёмочных
   примеров, decorators/параметризация, same-module helper context, hashes и явное
   различие заявленного исхода и реально наблюдавшегося результата. Он передаётся
   в гипотезу, предложение кода и существующий direct route. Положительный критерий
   достаточности добавлен без удаления scope_review. Применимость не привязана к VR.
3. Проведён настоящий `run_regression_cycle` / `run_project_development`.
   Новая гипотеза снова запросила scope_review. Выбран **явно**, только для этого
   опыта, существующий direct route. COS предложила код: первичная ошибка устранена,
   но заданная проверка HTTP400 с некорректным JSON выявила новую регрессию.
4. Исправлен разрыв COS: `build_regression_feedback` теперь принимает также отказ
   requested acceptance до передачи на исполнение. Проверяются hashes источника,
   кандидата, исходных тестов и receipt; регрессия повторяется на двух копиях
   кандидата, исходник должен проходить этот тест. Отклонённые права на применение
   не восстанавливаются; новый кандидат заново проходит все проверки. Эта обратная
   связь автоматически дошла до модели. Её второй патч прошёл27/27 и штатный Reviewer.
   Он установлен в VR вместе с двумя файлами приёмки; все50 исходных файлов
   проверены на актуальность перед записью, изменён один production-файл.
5. Сопоставлены артефакты и результат с предыдущим опытом. Сохранены отдельные
   происхождение кода, вмешательства ассистента и ограничения оценки.

## Что изменилось для пользователя VR

`src/dwg_normalizer/conversion_client.py:_request`: HTML/повреждённый JSON при
успешном HTTP больше не превращается в успешное пустое задание. Viewer API
возвращает503 с понятной ошибкой. Корректные JSON-объекты, исходные HTTP-статусы,
detail/reason fallback, сетевые ошибки, токен, кодирование имени файла и число
HTTP-запросов сохранены. DWG/PDF-корпус, геометрия и UI целиком не проверялись.
Работающий viewer не перезапускался; новый процесс загрузит исправленный файл.

## Оценка первых трёх ролей

| Критерий | Прежде | Теперь |
| --- | --- | --- |
| Analyzer: определить наблюдаемую причину | Причина описана правильно | По-прежнему правильно; гипотезный маршрут всё ещё останавливается на scope_review |
| Architect: получить допустимый вариант изменения | Проверенного варианта нет | Direct-предложение модели с native feedback принято; это не отдельный успешный LLM-дизайн Architect |
| SpecWriter: передать исполняемую спецификацию | `implementation_delta=blocked` | `implementation_delta=ready`, requested acceptance пройдена, Reviewer `approve` |
| Сквозной результат на этой задаче | 0/1 исправлений | 1/1, установлен точный модельный патч |

Штатный аудит передачи требований и полномочий был5/5 и остался5/5 — именно
поэтому один только audit раньше не показывал отсутствие полезного результата.
Числовые общие оценки ролей **не повышаются**: одна знакомая задача, выбранная
ассистентом, с его приёмкой и проверкой безопасности кода не является независимой
сертификацией9+ или9.7+. Модельный анализ и выбор direct route самостоятельно
COS не улучшила. Подтверждено полезное завершение одного ремонта и автоматическая
коррекция реальной регрессии, а не полная автономность первых трёх ролей.
