# COS без обязательного GeminiVM — 24 сентября 2026

По решению владельца Analyzer, Architect, SpecWriter и описание проектов
переключены на явный API-маршрут `deepseek/deepseek-chat` через шлюз 5.
Ролевой профиль `deepseek_roles`: timeout 180 секунд, выход 32768 токенов,
строгая локальная проверка JSON и схем потребителей сохранена.
Автоматического перехода этих ролей на GeminiVM или экспериментальную Ultra нет.
Общий L4.5 и его прежний резерв GigaChat остаются отдельными профилями.

Профиль `geminivm_pro` сохранён для явного экспериментального выбора, но ни один
рабочий профиль или резерв COS на него не ссылается. Реализация провайдера и
исторические результаты сохранены. Доработка и живые испытания GeminiVM заморожены;
открытые задачи провайдера отложены до отдельного решения владельца. Это не
утверждение, что их технические причины устранены, и не удаление провайдера из
общего шлюза других проектов. Переопределения модели через environment остаются
явным выбором оператора; уже запущенные процессы COS должны перечитать настройки.

## Парный эксперимент

Два существующих дефекта COS: поиск тестов мигрировавших плагинов и пропуск
импорта внутри тестовой функции при определении наблюдаемого production API.
Первый воспроизведён проверкой выбираемых путей (пять отсутствующих каталогов),
второй — повторяемым вызовом настоящего механизма binding на минимальных fixtures.
Это реальные механизмы COS с подготовленными ассистентом примерами; не внешний holdout.

До генерации сохранены исходники с SHA-256, сообщения, схема и отдельные критерии
Analyzer/Architect/SpecWriter. Модели получают одинаковые сообщения, без готового
ремонта, скрытых критериев и дополнительных уточнений. В одном ответе три ролевых
раздела; это оценка предложений по ролям, не прогон production role pipeline.
Код ремонта не запрашивается и не применяется. Оценивание выполняет ассистент,
поэтому результаты не преобразуются в независимые баллы 9+ или 9.7+.

Четыре запроса максимум. Один и тот же локальный JSON schema проверяется для
обеих моделей; wire format DeepSeek — json_object, Ultra — native json_schema.
Настройки: temperature 0, gateway top_p 0.9, выход 32768, timeout 180 секунд.
COS не повторяет запросы и не переключает модели. SDK DeepSeek в шлюзе допускает
два внутренних повтора без отдельной телеметрии: для них оставлены дополнительные
слоты, полный консервативный резерв 713216 токенов. Reported usage не является
доказательством полного биллинга или числа upstream HTTP. При ошибке/неизвестном
usage серия прекращается; исправляющих запросов не предусмотрено.

Результаты и review: `artifacts/api_roles_20260924/`.

## Результаты

| Задача | DeepSeek | Ultra | Решение по дизайну |
|---|---:|---:|---|
| Поиск тестов плагинов | 54,688 с / 3170 токенов | 24,468 с / 4252 токена | Оба отклонены |
| Импорт внутри теста | 81,359 с / 5388 токенов | 22,515 с / 6042 токена | Оба отклонены |

Все четыре ответа прошли строгую схему, получены без ручного восстановления;
gateway cache_hit=false и один выбранный маршрут в каждом запросе. Ultra сообщила
версию `GigaChat-3-Ultra:32.9.23.6`, retry_count=0. Для DeepSeek сохранён указанный
шлюзом `deepseek/deepseek-chat`, независимая версия upstream и число SDK-попыток
не подтверждены. Всего 18852 reported tokens, сумма длительностей вызовов 183,030 с.
Это не длительность всей работы: подготовка, offline review и проверки отдельно.
Неизвестного usage среди четырёх полученных ответов нет; полный биллинг не измерен.

**Analyzer.** На поиске тестов обе модели установили основную причину. На импортах
DeepSeek пересказала симптом и назвала обычный локальный импорт динамическим,
не указав `tree.body`. Ultra указала верный сборщик aliases в evidence, но в cause
ошибочно обвинила `_lexical_function_nodes` в потере ImportFrom. Прямой offline
вызов подтвердил, что этот обход ImportFrom содержит. Качество причины нестабильно.

**Architect.** DeepSeek предложила эвристику имени `test_{id}_competency.py`,
вместо явного владельца тестов. Ultra предложила чтение подсказок из README и
разрешила exit 0 при `no_tests`, а затем сама потребовала ненулевой код в
SpecWriter. Алгоритм работает с каталогами, хотя мигрировавшая цель — файл.
В задаче импорта обе модели не задали разрешение binding на момент конкретного
вызова с обработкой последующих присваиваний, удаления и условных веток.
Ни один дизайн не допущен к реализации.

**SpecWriter.** Ultra дала больше конкретных случаев, но часть противоречит её
дизайну; относительный импорт указан без структуры package, `import *` внутри
функции синтаксически недопустим. Обе модели пропустили существенные негативные
примеры. У DeepSeek случаи преимущественно описательные, без достаточной настройки
и точного отрицательного результата. Валидный JSON не обеспечил пригодную приёмку.

Числовые оценки зрелости ролей не меняются. Ultra в этой серии быстрее, но
подтверждённого преимущества для автоматического ремонта нет. DeepSeek сохраняется
временным рабочим маршрутом по принятому решению, а не как победитель по качеству.

## Следующее действие

Сначала довести один ограниченный дефект до исполняемой приёмки через настоящую
ролевую цепочку: явное владение тестами плагинов, без догадок по именам/README и
без успешного пропуска отсутствующих тестов. Конкретные отрицательные примеры
должны обнаруживать противоречие алгоритма и спецификации до запроса кода.
Протокол данной серии остаётся неизменным; её задачи уже не свежий holdout.
Повторять эти же вопросы с новыми подсказками ради повышения оценки не следует.

85 локальных тестов маршрутов, fallback, описания и structured inference прошли.
Финальная проверка этапа и структурный checkpoint записываются в `verification.json`.
Полный historical canonical suite не входит в этот этап; новые package/API
контракты не вводились, повторная сборка подпроектов не требуется.
