# GigaChat Max / Ultra: ограниченное сравнение 24 сентября 2026

Обе модели доступны через существующий аккаунт. Рекомендация — Ultra как
кандидат для следующего ограниченного испытания COS; менять основные модели
первых трёх ролей по этому результату рано. Max не показала достаточной причины
для переключения. Это пять генераций на двух задачах, а не общий рейтинг.

## Доступ и исправление шлюза 5

API подтвердил `GigaChat-2-Max` и `GigaChat-3-Ultra`. Фактически в ответах:
`GigaChat-2-Max:2.0.28.2`, `GigaChat-3-Ultra:32.9.23.6`.
[Официальная документация Ultra](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-3-ultra)
указывает новый API `https://api.giga.chat`; legacy endpoint не перечисляет Ultra.
Установленное сопоставление направляет GigaChat-3 с legacy host на новый API.
Ключи и machine-local конфигурация не копировались в артефакты.

В отдельной копии проекта 5 исправлены четыре файла: новый
`app/gigachat/bounded_completion.py`, адаптер, namespace кэша и тесты.
Явно выбранная модель получает полный контекст, `max_tokens`, `temperature`,
`top_p` и поддерживаемый формат; сохраняются usage и версия модели. Один вызов
адаптера делает одну попытку генерации без классификатора, обрезки, внутреннего
кэша или повтора. OAuth отдельно, без генерации. Старый auto-маршрут сохранён;
новые бюджетные гарантии на него не распространяются. Старые cache entries
не удалены: версия ключа отделяет их от нового контракта. Внешний cache hit
не является новым измерением расхода провайдера.

Неподдерживаемый `json_object` отклоняется до OAuth/генерации. Для COS здесь
нужно `response_format=false`; native `json_schema` имеет другую форму.
[Документация формата](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output).
Квалифицированные маршруты: `gigachat/GigaChat-2-Max`, `gigachat/GigaChat-3-Ultra`.
Текущие role profiles и defaults COS сохранены.

67 офлайн-тестов прошли, включая API→адаптер→фиктивный HTTP, большие сообщения,
параметры, usage, ошибки и отсутствие скрытых повторов. После явного согласия
владельца четыре файла установлены с резервной копией и проверкой хешей.
Шлюз перезапущен, `/health` отвечает. Два запроса с заведомо неподдерживаемым
форматом подтвердили загрузку нового обработчика без платной генерации.
При этом найден отдельный дефект общего HTTP mapping: `bad_request` отдаётся
как HTTP 502, а не 400. Исходная проверка статуса упала; находка сохранена в
`installed-validation.json` и очереди. Это не скрывается за успешным health.

## Протокол и результаты

Одинаковые сообщения внутри каждой пары, temperature=0.2, top_p=0.9,
выход до 32768, timeout 300 с; без повторов и fallback. Резерв шести слотов
694912 токенов, один слот Max не использован из-за отклонённого дизайна.
Живые запросы: COS BudgetedChat → проверенный адаптер из изолированной копии
шлюза → настоящий API. Они не проходили через HTTP listener установленного
шлюза; его wiring проверен офлайн, установка — хешами и негативным запросом.
Старые прогоны DeepSeek/Pro имели другие/непереданные параметры, поэтому их
нельзя использовать как строго контролируемое сравнение только моделей.

| Проверка | GigaChat-2-Max | GigaChat-3-Ultra |
|---|---|---|
| Formatter: пять фактических полей | 5/5 | 5/5 |
| Formatter: пригодный причинный дизайн | Нет: полезное условие, но нет точной передачи данных и разбора контрастов | Нет: неверно описывает исходный эффект, противоречивый предикат |
| Inventory: ожидаемые исходы T1–T7 | 7/7 | 7/7 |
| Inventory: алгоритм | Валидация после суммирования скрывает недопустимые отдельные количества; противоречит T5/T6 | Тип/положительность до суммирования, все проверки до изменения stock |
| Допуск к точному патчу inventory | Нет | Да, с замечаниями к тексту |
| Native приёмка точного патча | Не запрашивался | 13/13, без правок ассистента |

Ultra также неточно описала исходную обработку дубликатов и предложила лишнюю
копию stock для rollback. Пустой заказ двусмысленно упомянут в алгоритме, но T7
и итоговый код корректны. Эти дефекты не превращаются в «идеальный» балл.
У Max отказ в допуске не доказывает невозможность написать правильный код:
измерено противоречие дизайна, а генерация патча по протоколу не выполнялась.

Formatter — известный внешний случай с подсказками ассистента и сохранёнными
границами. Inventory — новый синтетический случай, составленный ассистентом.
13 тестов зафиксированы до запроса кода; исходник дважды дал 5 passed / 8 failed.
Один точный патч Ultra дал 13 passed; одинаковая коллекция и хеш тестов,
неизменённые исходники подтверждены. Проверялись атомарность отказа, дубликаты,
типы, пустой заказ, alias исходного словаря и отдельная копия результата.

| Генерация | Max: секунды / токены | Ultra: секунды / токены |
|---|---:|---:|
| Formatter design | 14,735 / 6864 | 15,805 / 7547 |
| Inventory design | 14,419 / 1702 | 12,594 / 1962 |
| Inventory patch | — | 9,012 / 2578 |

Всего 5 генераций, **20653 reported tokens**, неизвестных usage нет;
сумма времени генераций 66,565 с. Это не полное время инженерного цикла и
не денежная стоимость; тариф/биллинг не измерены. Нельзя заключать, что Ultra
всегда быстрее или выгоднее. Известный provider-side precached usage сохранён.

## Применение к первым трём ролям

Analyzer: обе читают явные факты, обе способны ошибиться в причинном объяснении.
Architect: Ultra пригодна для дальнейших проверок небольших задач с явными
инвариантами; на сложном formatter ни одна не дала принятого дизайна.
SpecWriter: правильные T1–T7 полезны, но противоречие алгоритму Max показывает,
почему отдельный корректный список примеров недостаточен.

Следующий эксперимент — Ultra против текущего маршрута на небольшой заранее
зафиксированной выборке реальных задач других проектов: единые входы,
параметры и acceptance, сначала отдельные Analyzer/Architect/SpecWriter, затем
целая цепочка и native результат. Не продолжать добавлять подсказки к старому
formatter. До этого постоянное переключение и новые оценки 9.x не обоснованы.

Evidence: `artifacts/giga_models_20260924/`: protocol/budget, сообщения и точные
ответы, `design-review.json`, baseline и native probes, `gateway-tests-final.xml`,
`installed.json`, `restart.json`, `installed-validation.json`, `verification.json`.
Исторический неизвестный расход прежней Pro-кампании остаётся неизвестным.
