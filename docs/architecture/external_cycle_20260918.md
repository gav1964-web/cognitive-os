# Внешний цикл Analyzer → Architect → SpecWriter, 18 сентября 2026

COS исправила внешний python-slugify точным модельным кандидатом: **81 native
test passed**, все 11 проверок полного цикла, Reviewer `approve`. Первая версия
исправила целевой тест, но сломала Unicode-режим и была отклонена. Повторная версия
получила реальный вывод регрессии; ассистент не редактировал модельный код.
Это один внешний development case с помощью ассистента, а не независимая
сертификация ролей или доказательство 9.7+.

## Пять результатов пакета

1. Заморожен `un33k/python-slugify`, baseline
   `499112de56e19f6ef0dcee32adff3696e4ef5753`, только тестовый overlay из
   `e52c35e34899bc21a389aa7f4fe5084423cf538c`. До модели: 80 passed / 1 failed.
   Заголовок исправления и тестовый delta прочитаны; upstream production fix
   не открывался. Задачу и пять выбранных acceptance сформулировал ассистент.
2. Analyzer: исправлены общие ошибки привязки. Полный nodeid выбирает метод
   нужного класса; файл упавшего теста исключается из production frames даже
   при нестандартном имени; экспортированная функция разрешается перед
   одноимённым подмодулем. Wildcard учитывает literal `__all__`, динамический
   список не считается доказательством экспорта. Модель указала область
   transliteration, но её объяснение изменения осталось общим. Дополнительный
   probe ассистента подтверждает пользу нормализации перед transliteration
   для конкретной строки; обобщённая причинная компетентность не установлена.
3. Architect/repair: первый кандидат прошёл targeted replay и пять требований,
   но native regression обнаружила `UnboundLocalError` из-за условного локального
   импорта. Reviewer потребовал rework. Ассистент передал исходный кандидат и
   фактический вывод регрессии в одну повторную попытку. Модель сама убрала
   импорт; второй точный кандидат проходит 81 тест. Автоматическая передача
   полного regression feedback в следующий цикл пока не встроена в orchestration.
4. SpecWriter: добавлены `propose_acceptance` и `materialize_acceptance` для
   проверки дополнительных тестов **до** реализации. Сохраняются исходные
   тесты, хеши, происхождение требований и модельных предложений; два baseline
   повтора сверяют точный выбор, исходы и неизменность. `NameError`/сбой setup
   не засчитываются как корректный assertion counterexample. Выполнение только
   в явно разрешённых копиях доверенного кода; это не security sandbox.
   Обе реальные попытки усилить тесты отвергнуты: сначала отсутствовал импорт,
   затем сохранились неверные Unicode/entity ожидания. В ремонт они не включены.
   `baseline_verified` проверяет воспроизводимость, не смысловую достаточность.
5. `project_description` 0.17.0 передаёт опциональные, явно выбранные reviewer
   свойства вызова одновременно writer и review. Знания и интерпретация остаются
   внутри плагина. Факты привязаны к исходникам; unsupported остаётся unknown.
   Два полных описания противоположных уже использованных fixtures: первое
   частично улучшено, второе по-прежнему неверно описывает рабочий default и
   гарантирует диагностический флаг. Общий рост качества не доказан. Произвольный
   итоговый текст ещё не связан автоматически с формальным свойством.

## Измерение и границы

Модель неизменна: `deepseek/deepseek-chat`, локальный управляемый шлюз,
timeout 480 сек. Пакет закрыт: **10 calls, 41 054 reported tokens, unknown 0**,
консервативный предварительный резерв 524800. Расход прошлых кампаний сохранён.
Обе repair попытки заняли примерно по 103 секунды каждая, включая их цикл.
Первичный сбор, исправления COS и инженерная верификация в эту latency не входят.

Внешняя зависимость `text_unidecode==1.3` установлена в devvenv для исторических
тестов; требования и зависимости пакетов COS не менялись. Исторический корпус
не изменён. Новая копия baseline осталась неизменной, delivery находится в sandbox.
Для unittest не включался assertion-plan, поддерживающий обычные `assert`;
передавались тексты исходных тестов. Дополнительные ручные probes не являются
самостоятельным результатом COS. Новых числовых оценок ролей нет.
