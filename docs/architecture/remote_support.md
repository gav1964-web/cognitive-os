# Удалённый ремонт COS через сообщения

Первый работающий маршрут, 28 сентября 2026. Внешний помощник получает только
экспортированный пакет и возвращает запрос контекста либо кандидат исправления.
Контроллер COS самостоятельно проверяет, устанавливает и возобновляет задачу.
Файловый обмен — основной выбранный транспорт, а не временная замена почты.
По решению владельца пакеты могут переноситься через проверяемый и контролируемый
файлообменник. Подключение SMTP/IMAP в план не входит.

## Ответственности

- `runtime/remote_support_protocol.py`: конверт `cos.remote_support.v1`,
  HMAC-SHA256, ограничения размера/путей и атомарная доставка.
- `runtime/remote_support_release.py`: снимки явно выбранных файлов,
  точные замены и запуск локально заданных команд новым процессом.
- `runtime/remote_support_supervisor.py`: обращение, лимиты, проверка,
  выбор активного выпуска, восстановление и повторная доставка результата.
- `tools/remote_support.py`: CLI обеих сторон и ограниченный проход inbox.
- `runtime/remote_role_job.py`: неизменяемая привязка ролевого задания.
- `runtime/remote_role_worker.py`, `tools/remote_role_worker.py`: адаптер
  продолжения принятой спецификации, учёт inference и независимая приёмка.
- `runtime/remote_support_accounting.py`: резерв контроллера и сверка ledger
  после завершения worker; поддерживает потерю итогового JSON.
- `runtime/remote_support_exchange.py`, `remote_support_windows.py` и
  `tools/remote_support_worker.py`: файловый исполнитель под отдельным Windows SID.

Это инфраструктура Execution, без знаний целевого проекта. Контроллер использует
stdlib и не импортирует код обновляемого выпуска. Его policy, состояние и ключ
находятся вне этого выпуска. Патч не может обновить контроллер или приёмку.
Подключение opt-in: прежние ролевые маршруты не переключаются автоматически.

## Протокол

Конверт: `schema`, `id`, `incident`, `reply_to`, `sender`, `kind`, `payload`, `mac`.
ID — 32 hex-символа. Максимум 2 MB; повторяющиеся JSON-ключи отклоняются.

| Вид | Направление | Содержимое |
|---|---|---|
| incident | COS → помощник | Цель, checkpoint, ошибка, hashes, исходники, полномочия, бюджет |
| context_request | помощник → COS | До 12 разрешённых путей и/или ID локальной диагностики |
| context | COS → помощник | Исходники, результат диагностики, остаток бюджета |
| patch | помощник → COS | Digest baseline, замены файлов, объяснение, usage |
| result | COS → помощник | Проверки, итог задачи, активный выпуск, накопленные расходы |

Обмен последовательный: ответ ссылается на последнее исходящее сообщение того же
обращения. Повтор ID с прежними байтами возвращает сохранённый результат без
повторного исполнения/списания usage. Иные байты того же ID, устаревший baseline
и ответ не на последнее сообщение отклоняются. `poll` обрабатывает до 64 файлов
и сохраняет входы в `processed/`, чтобы старые сообщения не блокировали новые.

Диагностика выбирает только локально определённые `reproduce` или `regression`.
Произвольной команды и запуска `resume` через context_request нет. Экспорт
ограничен явным списком; локальные config/ключи в пакеты не включаются.
Список и диагностические команды должны быть проверены владельцем развёртывания:
фильтр имён не обнаруживает любые секреты внутри исходников/журналов.

## Локальная policy и выполнение

Policy фиксирует `files`, `export`, `editable`, три `commands`, `failure_marker`,
`task`, `checkpoint`, `max_attempts`, `max_messages`, `max_seconds`, `expires_at`,
`max_tokens`, `prior_usage`. Команда содержит `argv` с абсолютным путём executable
и `timeout`; shell не используется. Digest policy проверяется при продолжении.
Опциональные `accounting` и `execution` описаны в
[контракте восстановления и раздельных прав](remote_support_recovery_20260928.md).
Живой ролевой worker требует `accounting: "role_ledger.v1"`.

`start` создаёт управляемый baseline и пытается выполнить исходную задачу.
Успех завершает работу без ремонта. Обращение создаётся при exit code 1,
совпадении заранее заданного маркера и сохранности исходников/контекста.
Неизвестная ошибка/таймаут дают `needs_operator`, не автоматический ремонт кода.

Получив патч, контроллер:

1. Проверяет подпись, обращение, порядок, лимиты, baseline и область изменения.
2. Воспроизводит исходный дефект в свежей базовой копии.
3. Проверяет исправленную копию командами `reproduce` и `regression`.
4. Создаёт выпуск, переключает `active.json`, запускает `resume` новым процессом.
5. При отказе возвращает baseline pointer и отправляет результат помощнику;
   после исчерпания лимита сохраняет `exhausted`.

Рабочая команда получает через `COS_SUPPORT_CONTEXT` файл с исходными `task`,
`checkpoint`, их digest и фазой. Адаптер задания обязан использовать checkpoint
и перепроверять действительность прежних результатов. Общая миграция состояния
после изменения валидаторов не реализована. Exit code 0 трактуется по заранее
заданному локальному контракту; подпись помощника не заменяет эту приёмку.
Адаптер может сохранить JSON в `COS_SUPPORT_RESULT`: `passed`, `usage`
(`reported`, `unknown_reserved`) и диагностические поля. При наличии результата
успех требует одновременно exit code 0 и `passed=true`. Расход добавляется и при
отказе worker; повторная доставка сообщения не учитывает его дважды.

Ролевой адаптер v1 принимает только `spec_qualified` без попыток Programmer.
Он связывает хешами цель, исходники, JSON checkpoint, соседний transcript
(включая его отсутствие), принятые роли/тесты, исходный ledger и внешний oracle.
Офлайн-проба повторяет native qualification и допускает ровно следующий вызов
Programmer, не отправляя его модели. Resume сохраняет прежний ledger и записывает
указатель нового до платного обращения. Неизвестный расход блокирует повтор.
Gateway проверяется/запускается перед созданием inference-учёта.
Опциональное поле задания `known_calls` связывает файлы истории с хешами;
worker проверяет их целостность и передаёт только как доказательства учёта кэша.
Кэш считается уже учтённым только при точном совпадении запроса, модели,
параметров и ответа с оплаченным slot в перенесённом ledger. История не используется
как replay ролевого решения. [Проверка под службой](remote_worker_8200_20260929.md).
Завершение требует review, проверенной сборки и отдельной внешней приёмки.
Исходный проект не устанавливается: результат — проверенный отдельный кандидат.

Для pytest в вложенном выпуске задавать `--import-mode=importlib --rootdir=.`:
иначе конфигурация/пакет тестов внешнего checkout может импортировать старый
runtime вместо кандидата. Это проверено на стенде 28.09; отсутствие source edits
само по себе не доказывает, что тест исполнял нужный выпуск.

v1 меняет только существующие разрешённые Python-файлы, максимум 400 строк каждый.
Новые production-файлы, удаления, изменения тестов, обновление контроллера и
миграции checkpoint не поддержаны. Старая версия и результаты попыток сохраняются.

## Прерывания и бюджет

ОС-блокировка освобождается при завершении процесса. Состояние и резерв времени
записываются до запуска проверки. При аварии в starting/processing/activating/
resuming контроллер возвращает baseline pointer и `interrupted_outcome_unknown`.
Задача, которая могла уже произвести внешние эффекты, не повторяется вслепую.
Откат указателя **не отменяет внешние эффекты**: их требуется сверить отдельно.

Предел токенов учитывает `prior_usage` плюс `usage.reported` и
`usage.unknown_reserved` последующих ответов. Сообщённый расход сохраняется даже
при отказе в допуске; дубликат не списывает его вновь. Внешний исполнитель обязан
соблюдать выделенный остаток и сообщать неизвестный расход резервом. Протокол не
контролирует чужой счёт провайдера; потерянный ответ не доказывает нулевой расход.
Протокольные/ACL-пилоты LLM не вызывают. Живой ролевой адаптер учитывает provider
usage; ни один из этих ledger не измеряет расход текущей сессии Codex.
После аварии контроллера локальная команда `reconcile --worker-stopped`
разрешает сверку расхода только после подтверждения остановки worker и не
разрешает автоматическое повторение задачи.

## Граница изоляции

Это runner доверенных аутентифицированных исправлений. Отдельные процессы и копии
**не являются OS sandbox**: под одним пользователем код технически может читать
иные каталоги. Для принудительной изоляции нужен отдельный worker в VM/контейнере
или под другой учётной записью с ACL. [Локальный Windows-пилот](remote_support_recovery_20260928.md)
проверил отказ чтения/записи ключа, состояния, policy и записи запроса под отдельным SID.
Это ограниченный стенд, не production sandbox. Ключ, состояние и policy контроллера должны
быть недоступны worker. Протокол сам не доказывает отсутствие прямого доступа.
HMAC использует заранее выданный общий ключ, не шифрует содержимое и не даёт
независимого доказательства авторства между двумя владельцами ключа.

## CLI

Ключ — минимум 32 случайных байта, переданных обеим сторонам вне mailbox.
Policy и команды готовятся локально для выбранного развёртывания.

```powershell
python tools/remote_support.py --key-file controller.key start --home controller-state --outbox to-assistant --source deployed-cos --policy policy.json
python tools/remote_support.py --key-file assistant.key reply --request to-assistant/ID.json --payload patch.json --kind patch --outbox to-cos
python tools/remote_support.py --key-file controller.key poll --home controller-state --outbox to-assistant --inbox to-cos
python tools/remote_support.py --key-file controller.key recover --home controller-state --outbox to-assistant
```

`poll` можно вызывать scheduler-ом. Он не запускает внешнего помощника:
на другой стороне нужен обработчик сообщений. Адаптер файлообменника переносит
тот же конверт без изменения payload. Файлообменник отвечает за доступ, доставку
и журнал передачи; контроллер COS независимо проверяет MAC, обращение, baseline,
полномочия и приёмку. Наличие файла в доверенном хранилище не разрешает исполнение.
Получатель скачивает пакет во временный файл без расширения `.json`, проверяет
завершённость передачи и только затем атомарно помещает его в inbox как `.json`.
Повторная доставка допустима: исходные ID и содержимое сохраняются. Ключи,
локальная policy и рабочая файловая система COS через хранилище не публикуются.
Конкретный сервис и его адаптер пока не настроены.
