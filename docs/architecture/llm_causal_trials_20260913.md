# Модельная гипотеза → проверяемое вмешательство, 13 сентября 2026

В `run_project_development` подключён ограниченный development-маршрут без
учебного оператора: существующий LLM hypothesis API получает наблюдаемый сбой и
исходник, затем второй запрос предлагает от одного до четырёх вариантов замены
одной функции. Это варианты вмешательства для одной гипотезы, а не доказательство
полноты поиска причин. Реальный native Replay проверяет каждый вариант.

Analyzer теперь разрешает точный квалифицированный путь метода: совпадение имени
метода другого класса не подменяет исходник. Перед запросом проверяются signed
packet, inventory, единственная цель и совпадение failure signature/nodeid.
В этом режиме KB не участвует даже при наличии знакомого учебного шаблона.

Architect получает результаты двух повторных baseline failure и patched native
тестов для каждого кандидата. Выбор возможен только при одном поддержанном варианте
и отсутствии неоднозначных/незавершённых проб. SpecWriter сохраняет сравнение в
delta, но её authority остаётся `none`: отдельный разрешённый trial не выдаёт
прав на доставку. Reviewer не принимает модельное происхождение за учебный рецепт.

## Контракт и ограничения

Включение: `authorize_training_replay=True`, `validate_causal_proposals=True`,
`llm_hypothesis_config=<явная конфигурация>`. CLI: соответствующие
`--authorize-training-replay --validate-causal-proposals --use-l45-llm`.
Прежний advisory без comparison и прежний учебный comparator сохраняют свои режимы.
Одновременный `task_contract` в новом модельном режиме пока отклоняется до работы.

На одну попытку — не более двух логических обращений к inference client, без
schema retry или автоматического нового цикла после неудачи. Его существующий
transport failover может сделать дополнительные HTTP-запросы; счётчик логических
обращений не выдаётся за биллинг. Оба обращения получают один объект конфигурации.
Цена и фактические токены требуют отдельной достоверной gateway telemetry.

Source module ограничен 16 000 символами; prompt кандидатов — 32 000, ответ —
40 000, replacement одной функции — 8 000. Все кандидаты проверяются до первой
исполняемой пробы, включая поздние невалидные строки. Используется существующий
AST editor, сохраняются аргументы, async-kind, return annotation и внешние
декораторы. Вне функции исходник сохраняется; поддержаны uniform LF/CRLF.
Смешанные переводы строк явно требуют ручного решения. Хеши связывают packet,
гипотезу, ответ и replacement; они не удостоверяют личность провайдера.

Проба запускает доверенный development-код в subprocess-копиях. Это не OS sandbox
для произвольного враждебного кода. Исходный проект не изменяется. Ответы и статусы
сохраняются в `artifacts/llm_causal_trials/trial-*/trial.json`, отдельные native
попытки — внутри указанного comparison receipt, включая отрицательные результаты.

## Evidence этого этапа

Использованы скриптованные ответы провайдера, реальные pytest subprocess и
ассистентская синтетическая фикстура shared pending list. Неверная перепривязка
списка отклоняется, изменение существующего списка проходит; два проходящих
варианта возвращают неоднозначность. Сквозной тест проходит реальные Analyzer,
Architect и SpecWriter, проверяет сохранение comparison и остановку до executor.
Подмены packet/target/signature/patch, изменение интерфейса, лишний код вне функции,
невалидные наборы, недоступный провайдер и отсутствие authorization проверены отдельно.

Первоначальный сквозной тест с `pass` правильно остановился: source analyzer добавил
наблюдение о заглушке к native failure, нарушив контракт единственного наблюдения.
Для поддержанного сценария фикстура изменена на обычный поведенческий дефект и
повторно проведён intake. Это исправление тестового setup, не расширение допуска.
В будущем нужно явно согласовать дублирующие наблюдения об одной цели.

Профильная регрессия: `artifacts/verification/llm_trials_v6_20260913.xml`.
Полный receipt этапа со снимком source, тестами и 400-line gate:
`artifacts/verification/development_stage_llm_trials_20260913.json`.
Архитектура: `artifacts/verification/canonical_llm_trials_20260913.json`.
Ошибочные ранние прогоны сохранены отдельно, их результат не считается успешным.

Живых model calls при этой разработке не было. Тесты подтверждают инженерный
контракт, но не качество генерации, независимый диагноз или 9.7+. Известный
EnvForge повторно не запускался и не переобъявлялся новым случаем.

## Продолжение

Передать выбранный неизменный модельный patch через Implementer/Tester и финальный
Reviewer, сохранив provenance и полную native regression; повторная генерация patch
должна требовать новой проверки. Затем связать requested requirements с этим
маршрутом, улучшить разрешение callers и проверить новый реальный development case
до помощи ассистента. Gateway usage и независимый judge остаются отдельными задачами.
