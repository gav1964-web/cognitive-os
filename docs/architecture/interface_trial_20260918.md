# Передача контекста и изоляция тестового inference — 18 сентября 2026

Пакет из пяти работ завершает проверку предыдущих результатов и исправляет два
инженерных дефекта. Принятого модельного ремонта по-прежнему нет.

## 1. Аудит шлюза и поправка к учёту

Предыдущий запрос с картой API завершился на шлюзе через 346,915 секунды,
после клиентского тайм-аута 240 секунд. Шлюз был доступен. Это подтверждает позднее
завершение, но не объясняет причину задержки. Кеш шлюза сохраняет только текст,
поэтому расход этого запроса остаётся неизвестным; старый receipt не переписан.

В интервале предыдущей финальной регрессии журнал содержит ещё **12 запросов
к локальной Qwen**, не отражённых в отчёте об эксперименте. Это ошибка изоляции
тестов и неполный учёт ассистента. Число 31 909 из прошлого отчёта относится
только к семи ответам контролируемой серии, а не ко всему этапу. Токены локальных
запросов неизвестны; эта проверка не является полным аудитом всей истории.

## 2. Восстановление описания без нового inference

Текст получен из единственной записи кеша с точным SHA-256 от provider, model,
полных messages и параметров запроса. Учтено представление temperature как
JSON float в шлюзе. Кеш прочитан без изменений, других ответов не перебирали.

Теперь можно сравнить оба текста предыдущей пары. Оба сохраняют повтор baseline,
проверку хешей и локальные wheels. Оба не удовлетворяют основному критерию:
валидный профиль необходим для успешной квалификации, хотя параметр сигнатуры
опционален. Вариант с картой также смешивает внутренний ValueError и поведение
публичного API. Преимущество не установлено; в лимит 240 секунд карта не уложилась.
Это оценка ассистента на знакомом проекте, не независимый benchmark. Default прежний.

## 3. Один ремонт с восстановленными интерфейсами

Два обращения DeepSeek: гипотеза и один кандидат, **15 726 reported tokens**,
без повторов и fallback. Резерв новых запросов — 260 960; прежний резерв 80 480
для неизвестного расхода сохранён отдельно, неизвестный расход не объявлен нулём.
Шлюз проверен штатным bootstrap. Исходный корпус не изменён.

Модель снова предложила неработающую проверку одного Comment. Полный native-прогон:
**33 passed, 1 failed, 2 xfailed**, новых регрессий нет, исходный дефект остался.
До финального Reviewer кандидат не дошёл. Уровни ролей не повышены.

Фактические запросы раскрыли дополнительный дефект COS: сигнатуры вызываемых
методов присутствовали в гипотезе, но терялись при передаче генератору кандидата.
Следовательно, этот прогон не проверил доставку интерфейсов через всю цепочку.

## 4. Исправления

Контекст вызовов теперь переносится из принятой гипотезы в запрос кандидата.
Он сохраняет идентичность номинации и входит в существующее хеширование advisory.
Предел запроса 32 000 символов и native/delivery gates сохранены. Запрос реального
случая после исправления проверен offline: 27 128 символов, одинаковый контекст
на обоих этапах. Новая модельная попытка после исправления не запускалась.

Извлечение интерфейса также поддерживает однострочные определения и UTF-8 имена;
тело функции не попадает в сигнатуру. Аннотации не считаются доказанными типами.

Автоматическая session-scoped fixture в `tests/runtime/conftest.py` блокирует настоящий urllib
transport к chat/completions, включая ранее импортированные model clients.
Скриптовые mock-ответы работают; остальные URL не блокируются. Это ограниченная
изоляция существующего LLM-транспорта, не общий сетевой или OS sandbox. Живые
измерения остаются в отдельных runner с бюджетом. Поведение продукта не отключено.

Первая версия блокировки была function-scoped: module-scoped подготовка данных
успевала сделать ещё **4 локальных запроса** в этом этапе. Первые 397 тестов
прошли, но эта версия не обеспечила изоляцию. Исправлена область действия;
добавлен тест именно подготовки модуля. Первые receipts сохранены с префиксом
`first_`; расход этих четырёх запросов также неизвестен. Сумма 15 726 относится
только к двум бюджетированным внешним ответам, не к общему расходу этапа.

## 5. Проверки и продолжение

Результаты итогового снимка, размерный gate и проверки архитектуры:
`artifacts/interface_trial_20260918/verification.json`. Новые проверки покрывают
запрет inference, совместимость mock transport, передачу контекста и отказ при
превышении прежнего бюджета. История отрицательных результатов сохранена.

Следующий ремонт должен проверить исправленную передачу через оба этапа.
Не считать одно восстановление контекста доказанным ростом качества. Для описаний
не расширять карту вслепую: сначала проверить, какие конкретные предусловия
теряются между чтением источников и финальным текстом. Отдельная задача шлюза —
сохранение usage и request identity после отключения клиента; кеш текста этого
не обеспечивает. Общий модельный timeout автоматически не увеличен.
